#+title: Scheme Graph benchmark
#+language: en

* Reproduction

Run =just benchmark-scc= from the gerbil-poo package root. The existing
Gerbil TestSuite uses the 2 GiB heap and production =-O2= policy. This run
used Apple M2 Pro, macOS 26.6.1, Gerbil =1cfb032=, Gambit =ea114fc= and
GCC 16.2.0. The reference checkout was =37f6dfc=.

Gambit's measurement vectors contain CPU time, wall time, GC CPU time,
collection count and allocated bytes. CPU includes GC.
Fixture construction, public source acquisition, prepared kernels and
output materialization have separate windows. A separate getter pass
does not contribute time to the public partition window.

* Algorithm selection

A verified source order gives singleton SCC labels directly. Other packed
graphs use Algorithm T with two private word vectors. After a nonleader
postvisit, complete entry, a low word reaching the first root and zero
prior retirement establish that the entire roster belongs to one SCC.
The kernel fills its existing label vector once. Other graphs finish the
ordinary traversal. Public partitioning still checks spanning paths and
quotient ranks against the original captured rows.

The same-index cyclic-band pair runs full, stop, stop, full with identical
representatives and groups. It checks edge visits, postvisits and
individual member retirement. Symbolic projection and canonical grouping
run outside the paired discovery window.
The public partition receipt distinguishes individual retirement from
=bulk-retired= and retains certificate counters.

- [[file:../generalized-graph.ss][Graph scheduling]] owns local rank repair and the resumable inverse
  closure. The rank receipt includes whole-roster source checks,

- [[file:../feedback-graph.ss][Feedback Graph]] consumes the certified partition for condensation.
  [[file:../component-revision.ss][Component revision]] binds old inverse work to the current staged
  ticket and retires it on successful publication.

* Owned revisions

The =d43578f= checkout passed a fresh =just benchmark-scc= run. The
existing =GRAPH-OWNED-DELTA= pair revises the same out-of-order edge on
the same prepared DAG. Each arm makes four observations per size and
checks the changed read and measured work. The final order agrees with
unrestricted repair and passes an independent order validator. Preparation
and explicit order enumeration sit outside the revision window.

|--------+-----------------+--------------+-----------------------+--------------------|
| 100,000 | 54.205–54.815 | 0.069–0.126 | 100,000 | 1 |
| 1,000,000 | 552.426–604.882 | 0.061–0.096 | 1,000,000 | 1 |

Both arms perform zero whole-index copies and materialize zero order
entries. Each opens two search buckets and writes two ranks. At one
million owners, the owned arm takes 0.060–0.096 ms wall, allocates
115,792–116,384 bytes and records no timed GC. The ordinary arm checks
all owner sources before applying the same sparse order repair.

The same suite measures ConstructionCache support replacement separately.
At one million owners the revision checks two owner rows and one retired
provider's reader, with zero whole-index copies and zero order entries.
The complete-suite sample takes 31.778 ms CPU and 32.034 ms wall. It
allocates 393,232 bytes with no timed GC. The later explicit reuse
projection takes 25.551 ms CPU. Both windows appear separately in
=GRAPH-OWNED-CACHE-SUPPORT=.

The million-owner pressure cases separate cold SCC preparation from the
edit. The ring cut takes 0.075 ms CPU and represents one million singleton
components without enumerating them. The hub edit takes 0.196 ms CPU and
removes one reverse edge. Cold preparation takes 18.780 and 16.645 s CPU,
respectively, including 7.872 and 6.770 s of GC. Full approval is another
window. The 10,000-group hub publication checks all groups and takes
11.409–16.650 ms CPU per deletion.

The fresh build takes 361.85 s wall and the complete benchmark suite
takes 646.44 s wall. The suite includes cold setup, explicit projections,
SCC and reachability workloads, and semantic differential checks. These
totals describe the full suite. The table describes one edge revision on
a prepared Graph.

* Acceptance

The complete =just benchmark-scc= TestSuite exited normally after
468.31 s wall, with build time measured separately. The reference suite took
498.01 s wall. The suite includes the original 320 paired SCC
observations, 48 capture/discovery observations, 96 small reachability
observations, 32 membership observations, 32 rank updates and the new
four-window completion pair. Total suite time covers all these workloads.

Five focused Gerbil suites passed for Graph properties, feedback,
local order repair, component membership/publication and recursive
validation. They retain the 512 exhaustive three-owner graphs, seeded
POO generators, structural oracles and existing rejection controls.
Removing only the zero-prior-retirement guard in an isolated compiled
copy makes the exhaustive and seeded cases fail with an invalid SCC
spanning certificate. The ordinary test entrypoint exits with code 1.

The separate Yuanxu 10,000-Module EVAL acceptance has its own workload
and budget.
