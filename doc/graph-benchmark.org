#+title: Scheme Graph benchmark
#+language: en

* Reproduction

Run =just benchmark-scc= from the gerbil-poo package root. The existing
Gerbil TestSuite uses the 2 GiB heap and production =-O2= policy. This run
used Apple M2 Pro, macOS 26.6.1, Gerbil =1cfb032=, Gambit =ea114fc= and
GCC 16.2.0. The reference checkout was =37f6dfc=.

Gambit's measurement vectors contain CPU time, wall time, GC CPU time,
collection count and allocated bytes. CPU includes GC.
Fixture construction, public source acquisition, prepared kernels and
output materialization have separate windows. A separate getter pass
does not contribute time to the public partition window.

* Local compiler memory

The Scheme heap limit applies to the test VM. For local native preparation,
wrap the existing Just entry point with the Gerbil Bazel process-tree guard
so the same budget also covers GCC and its =cc1= children. For example, with
=guard= pointing to =gerbil/resource_guard_v19.ss= in the Gerbil Bazel checkout
and =receipt= pointing outside the build prefix:

#+begin_src sh
GERBIL_BUILD_CORES=1 GERBIL_BAZEL_GUARD_MAX_RSS_BYTES=4294967296 \
  GERBIL_BAZEL_GUARD_SAMPLE_SECONDS=0.1 \
  gerbil -:max-heap=256M,debug=q "$guard" "$receipt" graph-build 0 \
  just build-graph-study
#+end_src

The sampled memory threshold can be crossed between samples. An
=rss-limit-exceeded= receipt is a failed build. Use a fresh isolated prefix
for the next verification if the interrupted build left partial products.

* Algorithm selection

A verified source order gives singleton SCC labels directly. Other packed
graphs use Algorithm T with two private word vectors. After a nonleader
postvisit, complete entry, a low word reaching the first root and zero
prior retirement establish that the entire roster belongs to one SCC.
The kernel fills its existing label vector once. Other graphs finish the
ordinary traversal. Public partitioning still checks spanning paths and
quotient ranks against the original captured rows.

The same-index cyclic-band pair runs full, stop, stop, full with identical
representatives and groups. It checks edge visits, postvisits and
individual member retirement. Symbolic projection and canonical grouping
run outside the paired discovery window.
The public partition receipt distinguishes individual retirement from
=bulk-retired= and retains certificate counters.

* Scheme paths under test

- [[file:../strong-components.ss][Strong components]] owns ordered reachability, packed capture,
  source-rank selection, Algorithm T, canonical normalization and
  independent partition certification.
- [[file:../generalized-graph.ss][Graph scheduling]] owns local rank repair and the resumable inverse
  closure. The rank receipt includes whole-roster source checks,
  snapshot copies and order materialization.
- [[file:../feedback-graph.ss][Feedback Graph]] consumes the certified partition for condensation.
  [[file:../component-revision.ss][Component revision]] binds old inverse work to the current staged
  ticket and retires it on successful publication.

** First owner replacement after collection

The controlled Scheme probe keeps the same schedule and ConstructionCache
snapshot on each arm. It populates Gambit object serials for the fixture
owners, collects outside the measurement, and alternates whether one serial
lookup or the complete owner replacement runs first. The replacement adds
one owner, retires one and updates its sole reader. It retains the exact
provider value and checks both generations after each measurement.

| Owners | Original replacement first, CPU ms | Stable comparison replacement first, CPU ms |
|--------+------------------------------------+---------------------------------------------|
| 100,000 | 2.287–2.477 | 0.303–0.346 |
| 1,000,000 | 18.839–20.432 | 0.312–0.427 |

Both revisions report zero collections within the timed interval. In the
original million-owner arm, one cold serial lookup takes 18.930–19.622 ms
CPU when it runs first. The following replacement takes 0.341–0.556 ms.
With shared symbolic comparison, the serial lookup still takes
15.817–15.974 ms after the replacement. Graph-only comparison leaves the
tail in place. Changing the prototype-map name index reduces the isolated
schedule application to 0.107–0.118 ms, while the complete revision still
pays for the first slot shape construction. Sharing the order across
the three paths removes this serial-table access for distinct hashes. The
final comparator uses the serial tie for all hash collisions, since an
uninterned symbol can retain the mutable source string. The ordinary
native suite rejects a spelling-based comparator after the caller mutates
that string and independently rejects omission of the identity tie.

This probe deliberately populates the runtime serial table and forces a
collection. The ordinary =owned-cache-benchmark-test= retains its natural
collection behavior and separately measures explicit reuse output.

The natural standalone suite was run baseline, stable, stable, baseline.
For 1M owners the support replacement took 0.345–0.619 ms CPU and
0.341–0.656 ms wall on the baseline, versus 0.310–0.337 ms CPU and
0.309–0.336 ms wall with stable comparison. Both arms evaluated two
owners, checked one retired reader, copied zero index entries, and
enumerated zero order entries. The timed interval had zero GC and
allocated 394,704 baseline or 395,152 stable bytes. Maximum resident
set size across the complete invocations was 1,402,732,544–1,464,270,848
baseline bytes or 1,440,169,984–1,462,861,824 stable bytes.
The original complete baseline suite observed a 35.983 ms CPU sample
after its earlier workloads. The natural standalone sample and forced-GC
experiment describe different runtime serial-table states.

* Acceptance

The complete =just benchmark-scc= TestSuite exited normally after
468.31 s wall, with build time measured separately. The reference suite took
498.01 s wall. The suite includes the original 320 paired SCC
observations, 48 capture/discovery observations, 96 small reachability
observations, 32 membership observations, 32 rank updates and the new
four-window completion pair. Total suite time covers all these workloads.

Five focused Gerbil suites passed for Graph properties, feedback,
local order repair, component membership/publication and recursive
validation. They retain the 512 exhaustive three-owner graphs, seeded
POO generators, structural oracles and existing rejection controls.
Removing only the zero-prior-retirement guard in an isolated compiled
copy makes the exhaustive and seeded cases fail with an invalid SCC
spanning certificate. The ordinary test entrypoint exits with code 1.

The separate Yuanxu 10,000-Module EVAL acceptance has its own workload
and budget.
