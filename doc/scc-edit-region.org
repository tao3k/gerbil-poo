#+title: Exact SCC repair over a batch of changed rows

The general fixed-support branch of =revise-partition= uses the old forward
and reverse indices plus added edges. The resulting union =U= is the old
and new graph's edge union, even when the batch also removes edges. It
intersects nodes reachable from an edited root in =U= with nodes that can
reach an edited root in =U=. The roots for the two paths can differ.

[[file:scc-edit-region.lean][Lean]] checks six main obligations:

- =old_with_additions_exact=: the overlay has precisely the union's edges.
- =outside_membership_exact=: old and new SCC membership agree for a node
  outside the region. Otherwise a mutual path through a changed row would
  witness both directions of reachability between that node and a root.
- =induced_membership_exact=: paths between region vertices can stay inside
  the region. Restricting to successor edges there preserves mutual reachability.
- =no_crossing_component=: an old or new SCC touching the region is wholly inside it.
- =patch_exact=: keeping the old relation outside and using the new induced
  relation inside yields exactly the cold successor SCC relation for all pairs.
- =first_representative_exact=: exact membership on the same source roster
  yields the same first member, independent of discovery order.

The checked two-node counterexample cuts one edge of a cycle. The new-only
walk misses a vertex whose SCC changes. The proof allows multiple edited
roots and arbitrary simultaneous additions and deletions; it does not require
that every admitted root actually changes its edge set.

[[file:scc-edit-region.sysml][SysML]] records the refinement boundary. This is a relational proof for the
existing general repair branch. It assumes the Scheme walks yield exact
reachability and the unedited rows agree. It does not prove the native bucket
iterator, source-order representative construction, or publication. The
ranked singleton and retained-components laws are recorded in
[[file:performance/retained-scc-direction.org][Retained SCC direction]].
Those gates remain separate; a vertex outside the SCC repair region can still
be a downstream consumer. No Scheme path or QNT transition changes here.

* One changed row and a certified ring cut

| Existing Scheme branch | Lean result | Admission premise |
|------------------------+-------------+-------------------|
| =single-removal?= | =single_removal_exact= | One changed row; no added edges. The union is the old graph, so both walks intersect in the cut owner's old SCC. |
| =functional-cut?= | =functional_replacement_exact= | One old successor per row, one removed edge at the cut row, no added edges, all other rows unchanged. The cut row becomes a sink. |
| Singleton owner/member projection | =functional_repair_exact= | The old whole component can reach the cut from every owner. A surviving path follows the unique successor and reduces the distance to the sink whenever it reaches another owner. |
| ='all-representatives= | =every_group_changed= | A whole old component had at least two members. Even the group named by the old representative changes membership. |

The original =own-partition= shape check establishes one whole component
with at least two owners and one outgoing edge per row. The edit path uses
that certificate only after exact row differences are admitted. An internal
chord can retain the old component while invalidating its one-successor
shape: Lean checks a three-node chord whose cut leaves a nontrivial SCC.
The native chord cases check that retaining membership retires the shape
before later deletion. The same suite passed 128 deterministic compound
edits against cold groups, representatives and rows.

The existing ring and Hub pressure suites were run through Just with the
prepared Graph study, the =cc319ed= scheduling candidate and the unchanged
2 GiB heap fence. Both sizes pass the original assertions, including exact
ordered singleton output and quotient sentinel. CPU milliseconds:

| Ring | 100K | 1231.275 | 0.086 | 0.671 | 0.077 |
| Ring | 1M | 16307.569 | 0.077 | 6.581 | 0.091 |

There are zero old forward/reverse bucket scans or induced-region edge

reverse bucket rewrite. Ring edits allocate 76,736 bytes without GC;
explicit 1M singleton output allocates 96,000,288 bytes without GC.
Cold capture collects, so allocation there is unqualified. The invocation
exits naturally in 44.61 s wall with Module/Harness/final OK. No peak RSS
was captured. These are correspondence observations on the current path,
not a before/after performance claim or a real Module EVAL result.

* Handoff to the quotient and value invalidation

Two different reverse walks serve different purposes:

1. With fixed quotient support, seed every edited reader row (and any value
   edits). =old_inverse_exact= proves that the old and successor reverse
   closures agree. A path into the dirty set only needs its prefix to the
   first dirty vertex; every edge in that prefix has an unedited source.
   This justifies old-index continuation in
   =%apply-schedule-revision-with-invalidation= under the authenticated
   schedule ticket. It does not justify using an old ticket after commit.
2. When a provider changes representative, look up its readers in the
   successor's vertex inverse. For a group with unchanged representative,
   ordered members and ordered rows, =routes_unchanged= proves that unchanged
   provider representatives preserve the entire ordered route projection.
   Conversely, =changed_route_requires_remapped_provider= gives an actual
   provider in the row whose representative changed. The successor inverse
   must therefore lead back to that reader, even if the reader's SCC was
   outside the repair region. =changed_group_is_seeded= proves that an exact
   transpose maps the witness to the reader's successor group. This is the =remapped= walk in
   =revise-partition=. Membership and direct source edits have their own seeds.

Support edits keep their existing successor-inverse fallback. The existing
owned split/merge case in
[[file:../t/components/component-membership/component-requests.scm][component-requests.scm]]
checks two quotient reader edges, the outside =settlement= recomputation,
retention of unrelated values, and equality with a cold split. The separate
10,000-owner rank-repair case checks an outside consumer without requiring an
SCC change. These tests exercise distinct paths; neither is a real Module
EVAL fixture. This proof change introduces no new Scheme workload.

Reproduce with =lean +leanprover/lean4:v4.35.0 doc/scc-edit-region.lean=.

* Isolated owner retirement

The existing POO source, SCC and ConstructionCache indexes now remove an
isolated owner using its admitted stable ordinal. The successor shares
the remaining forward and inverse indexes and ordered roster. The full
order is still enumerated explicitly. The source and value witness trees
retire the same owner. An old snapshot still checks its original source
support and can become stale through a retired role. The successor no
longer depends on that role.

=membership_delta_support_exact=, =padded_scc_exact= and
=retired_ordinal_is_isolated= give the graph and roster conditions.
A surviving value is reusable only when the exact native member builder
and default construction policy authorize that locality. The Scheme
coordinator also checks the actual graph predecessor, empty incident
buckets and unchanged surviving programs. An opaque builder can inspect
the whole roster, so it retains full admission. The Lean counterexamples
=retired_member_can_change_opaque_builder= and
=local_value_with_changed_policy_cannot_be_reused= capture those independent
boundaries. Replacing the construction policy or denying joint approval
keeps the old snapshot.

* Authored effects and native replay

Use private table seeds inside authenticated native preparation. Exit that
scope for author row reads, lens initialization and methods, member
equations, cooking and joint approval. Inspect existing native lens cells
without instantiating a cold lens or issuing a semantic read.
=cold_lens_admission_runs_only_original_preparation= describes that gate.
=private_closure_steps_preserve_application_result= preserves application
effect order and the first refusal. =native_prefix_preserves_author_checkpoint=
states the application-state equality required when full and local native
preparation perform different work.

An admitted program owns its exact existing read traversal directly. It
authenticates the live route, issued records and receiver state before
invocation and on return. The stock quotient uses the same guarded program
action as the ordinary source wrapper. Open builders and observation routes
keep that wrapper. =retained_program_rechecks_after_callback= and
=open_owned_method_preserves_observer_refusal= describe these boundaries.
Empty and singleton dependency rows retain shape checks and avoid an
unneeded duplicate table, as proved by =component_row_dedup_at_most_one=.

The matching faults removed the private-to-application handoff, replaced
the lens readiness check with an eager lookup, and omitted the program
checkpoint. Each was rejected by its corresponding native test. The
prototype that retained synthetic projection receivers reduced random
source draws but did not improve CPU reliably and changed the approval
draw. The final implementation retains the traversal itself and uses the
existing POO replay path.

* Native acceptance

On the same 10,000-owner fixture, four serial macOS rounds forced full
reconstruction or used isolated retirement in full/local/local/full
order. All returned normally under the 180-second watchdog. The six-word
default random-source state at approval matched in all rounds. Across six
retirements per path, median CPU was 2.528 seconds and 104 microseconds,
and median wall was 2.540 seconds and 106 microseconds. Whole-process peak
RSS including startup was 2.05–2.06 GiB and about 0.97 GiB, respectively.
The local retirement had zero collections and 180,192 bytes median
attributable allocation. Full allocation was unqualified.

The existing =just benchmark-scc= suites completed with the 100,000 and
1,000,000 node cases, including chain, hub, skew, cycle, ring deletion,
reverse hub deletion and owned inverse continuation. Those are POO Graph
workloads. Incident roster edits still use the existing full support-change
path where an isolated retirement proof is unavailable. Real Yuanxu
Module EVAL has its own runtime and source admission gates.

* Local admission of appended owners

For an admitted owner append with the stock Builder and a certified
member-local group builder, the Scheme publisher starts from the exact admitted partition,
reserves fresh positions after its high-water mark in request order and
initializes the new vertices as isolated singletons. No old row gains an
edge in that step. =appended_ordinal_starts_as_singleton= establishes
the starting SCC for a fresh position, and
=append_preserves_old_representative= preserves every old ordered member
list, hence its first representative. New active owners and touched rows
then enter the existing SCC repair on the enlarged domain.
=append_ordinals_are_fresh= establishes ordinal disjointness and
=append_patch_exact= applies the existing region theorem to this padded
predecessor, yielding the cold successor SCC relation. Rows and member
groups untouched by the edit keep their old indexes. Appending any vertex
retires the whole-functional-cycle certificate even before the first edge
edit. Retired ordinal tombstones do not become active through append.
If a retired name is added again, it receives a new position and no
old program, base, route or witness. Explicit roster output checks that
the position being enumerated equals the active position for the name,
so the old occurrence stays hidden.

The source and quotient guard trees both address witnesses by source
position. If the existing span is too small, double it until the last
appended position fits, placing the existing root under the new left
child at each step. This works for the existing arbitrary initial span:
=grown_left_span= proves the split recovers that span exactly.
=witness_growth_preserves_address= proves that old lookups retain the
same address, and =witness_growth_leaves_new_address_empty= shows new
positions have no inherited witness. New ancestors must register their
native POO dependency on their shared child before testing currentness,
with the same already-dirty check used by the existing splice. A pending
revision still has to pass source and publication checks independently.

The Scheme splice now builds the new ancestor paths directly, borrowing the
old subtree at its original span and registering children before parents.
The quotient guard requests growth from the positions in its changed rows.
The native witness test grows a span of three to twelve, checks subtree
identity, and invalidates old and new inputs separately. It also expands
an already-stale root to verify the new ancestor refuses it.
In the isolated fault build, dropping the dependency edge to the reused
root leaves the expanded sibling current after the old input changes.
The same native assertion refuses that build with test exit 42.

The source and padded partition share one position index. The roster adds
one suffix, and guard growth uses the same positions. The quotient compares
the repaired groups with the real predecessor: a new singleton that merges
immediately is never retired from the predecessor, and a surviving new
representative must be installed. Every appended owner seeds invalidation
through its final group. Opaque builders and batches combining addition
with removal use full support admission. The structural proofs cover
the padded partition and witness addressing; native registration,
ticket retirement and value reuse have separate checks.

** Native checks

The component publication test appends an isolated owner, retires it and
adds the same name again at a fresh ordinal. A second test joins two old
groups through a new owner, compares the groups and outside reader with
cold publication, and verifies an approval refusal preserves the old
head. Passing the new owner's temporary representative through as a
predecessor retirement makes the matched fault fail with =unsupported c=.
