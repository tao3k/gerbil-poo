#+title: Graph search frontier: ordered private prefix candidate

* Existing boundary

=repair-order= materializes the bucket, charges every edge (including pruned
boundary edges), then selects the bounded-rank frontier and appends it before
the existing pending tail. Admission and rank repair are separate boundaries.
This experiment leaves bucket materialization and edge accounting untouched.
It considers only removing a temporary selected-prefix copy.

* Contract before Scheme

[[file:graph-frontier.lean][Lean]] proves left-to-right predicate evaluation with arbitrary state and
refusal equals a reversed private accumulator followed by reverse-append.
The result, predicate order, first error and its complete state are equal.
[[file:graph-frontier.sysml][SysML]] requires disjoint ownership: every accumulator cell must be fresh.
Gerbil's public =append-reverse!= primitive can relink only that private prefix;
the borrowed bucket and old pending tail remain read-only. The proof models
the primitive's sequence contract; native implementation and allocation are
separate runtime obligations. Never pass the borrowed row to the primitive.

No new public API, wrapper, evaluator, loader or cache is proposed. Independent
effects and edge accounting must remain in their original positions.

* Experiment before adoption

Use the optional cold-preparation study, existing native structural rank index,
same admitted row and same predicate on both arms. At 100K/1M, distinguish empty,
sparse and dense selected frontiers; retain ABBA/BAAB and A/A/B/B with natural GC.
Check exact sequence, shared pending-tail identity and unchanged borrowed row
outside timing. Preserve slower samples and unqualified allocation endpoints.
Do not infer a complete rank-repair or Module EVAL speedup from this kernel.
Production search stays unchanged until functional, matched-fault, CPU and
original end-to-end gates support the candidate.

* Native result: reject universal private accumulation

The focused study passes sequence, shared-tail and borrowed-row assertions,
with Module/Harness/final OK and natural exit (8.80 s wall). All paired windows
below have zero collections. CPU medians in ms, four samples/arm:

| Size | Selected | Original filter+append | Private reverse-append |
|------+----------+------------------------+------------------------|
| 100K | empty | 9.8230 | 9.9300 |
| 100K | sparse | 9.7655 | 9.9035 |
| 100K | dense | 10.4940 | 10.0600 |
| 1M | empty | 73.4220 | 74.3930 |
| 1M | sparse | 72.6055 | 74.7860 |
| 1M | dense | 86.2685 | 77.0540 |

The sparse/empty work does not improve. At 1M dense, A/A is 84.930/87.606 ms,
B/B 95.880/86.744 ms; same-side variation cautions against generalizing the
paired gain. 1M sparse A/A is 95.770/77.325 ms and B/B 84.987/100.170 ms.
Keep every sample, including these slower controls. No universal replacement
or unmeasured density dispatcher is adopted. Plain rows retain filter+append.
The [[file:graph-bucket-walk.org][edited reverse bucket study]] evaluates the
separate case where streaming also avoids materializing the bucket.
The separate [[file:graph-rank-bounds.org][DAG rank-bound contract]] instead targets redundant queries
using certificates that the existing algorithm already maintains.
