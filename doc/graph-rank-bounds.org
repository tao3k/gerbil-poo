#+title: Use the admitted DAG to bound local search

* Contract before Scheme

In =repair-order=, all deletions precede additions. Each addition is searched
before insertion; previous additions have already been checked and relabelled.
The current DAG therefore certifies provider rank < consumer rank at search
entry. Forward search starts at =high=, reverse search at =low=. Every accepted
pending owner remains in that interval; the same inductive premise applies to
its next row. [[https://github.com/tao3k/lean-poo/blob/bbba642946c7ef98c98eee52387013e9da2fd171/LeanPoo/Proof/Gerbil/GraphRankBounds.lean][Lean]] proves the per-row sequence equalities:

- Forward: rank(provider) < rank(owner) <= high, so only low needs checking.
- Reverse: low <= rank(owner) < rank(reader), so only high needs checking.
- Forward low=0: every row member qualifies, with no rank query.
- Reverse high>=frontier-1: every live reader qualifies, with no rank query.

The rank frontier is monotone, not the active owner count. Cold ranks are
0..N-1; relabelling permutes old labels, new owners append labels, and removal
leaves holes. The patch and reused-label theorems preserve bounds without
enumerating the complete support. [[file:graph-rank-bounds.sysml][SysML]] records these obligations.

This is not permission to drop an arbitrary predicate: rank reads are internal
immutable index operations on already admitted owners. No author callback,
Gerbil expansion, source currentness, unsupported-owner refusal or publication
check is removed. Unknown-source =reschedule= keeps its full authentication.
Bucket materialization, edge accounting, frontier output and incident checking
stay in place. The candidate adopts only the two complete-range shortcuts;
partial intervals retain the original two-bound predicate and query path.
The one-sided theorems justify the complete shortcuts, not a claim that the
partial-interval implementation has been replaced or measured faster.

* Validation

Keep the existing construction and 100K/1M rank/owned-Delta suites. Add a focused
interval-boundary fixture that observes both outside providers and outside
consumers, plus forward-floor and reverse-ceiling cases. Force the complete
range branch on partial intervals as a matched fault: extra expansion must fail
the work oracle, not time out. Benchmark empty/sparse/dense admitted monotone
rows in both directions, with the same native index, natural GC and same-side
controls. Complete output order and historical buckets remain unchanged.

* Qualification

Lean 4.35.0 accepts all ten named theorems with no sorry axiom (only standard
propext/Quot.sound where needed). A finite counterexample also rejects replacing
the rank frontier with active cardinality after deleting a label.

The construction group passes all 43 cases, including forward floor, reverse
ceiling, interval-external providers/consumers and deletion holes. Two deliberate
faults are compiled and executed through the same official Just test entry:

- Force complete=true: partial-interval search opens 4 buckets instead of 2.
- Substitute active cardinality for frontier: the deletion-hole fixture opens
  3 buckets instead of 2.

Both fail real work assertions with exit 1, not timeout or compiler errors.
After restoration the final 43 cases exit naturally with Module/Harness/final
OK (22.84 s wall, 3.19 user, 0.50 system); the earlier hole run is retained too
(4.66 s wall). Do not attribute this wall gap to the search without scheduling
evidence. Test code uses its existing -O2/-D___SINGLE_HOST_LIMIT=4096 policy;
the first diagnostic without the latter is not the accepted policy build.

The existing 100K/1M rank and owned-Delta integration retains all 32+16 paired
observations and original work/output oracles, with Module/Harness/final OK
and natural exit (58.42 s wall). No Core 10K or downstream gate is implied.

* Merge captured repair labels

The local repair already sorts the provider and consumer frontiers by
old rank. A candidate captures each affected rank once before the
first assignment, sorts the two frontiers by their captured ranks,
and merges those rank streams while assigning providers before
consumers. =merge_repair_labels= proves equality with sorting the
concatenated rank labels again. The incident checks retain the same
owner order and still use the successor ranks.

The focused Darwin =-O2= build took 19.93 s at 1.40 GiB sampled
process-tree peak. All 22 local order cases passed. In the complete
100K reverse-hub repair, both arms examined 99,999 live edges and
rewrote 100,001 ranks. The reference/candidate CPU medians were
648.43/452.60 ms, wall medians were 701.32/459.77 ms and GC CPU
medians were 75.84/73.55 ms. Each sample collected once, so allocation
estimates are unavailable. Peak process-tree memory was 0.77 GiB
in both arms after rounding. The earlier queue-only candidate
measured 612.49/640.12 ms CPU on its own four-arm comparison.

The isolated 1M reference printed the cold construction entry and
failed the 2 GiB Scheme heap fence before the exit marker. The 4 GiB
process-tree guard measured 2.28 GiB at that failure. There is no
million-reader rank timing for either arm. The merge candidate remains
in the experiment pending that comparison.
