#+title: Component family membership

* Prepared families

=component-group-builder= owns a copy of the declared family keys and
selects each focus once in declaration order. Its private =lenses= table
already maps each family key to its Lens. A group request can use
=hash-key?= on that table to check that all requested keys belong to the
family. An absent key is refused before any component program runs.

The builder uses Gerbil's standard identity-table methods for membership.
A focus callback can replace a table method, so the builder checks the
current lookup and write methods before using the index. If the check fails,
membership uses the owned list for the rest of that builder's life.

For example, suppose a family contains =invoice=, =tax= and =rate=.
If =invoice= and =tax= form an SCC, the =tax= read inside the =invoice=
equation uses the current fixed-point input. If =rate= is in a predecessor
SCC, its read uses the closed predecessor value. All three keys pass family
membership. The equation uses its current SCC members to choose the source.

An experimental index for the SCC itself increased a sparse cold lookup at
one million members from 4.6830 to 180.0730 ms CPU and was withdrawn.
