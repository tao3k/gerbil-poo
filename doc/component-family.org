#+title: Component family membership

* Prepared families

=component-group-builder= owns a copy of the declared family keys and
selects each focus once in declaration order. Its private =lenses= table
already maps each family key to its Lens. A group request can use
=hash-key?= on that table to check that all requested keys belong to the
family. An absent key is refused before any component program runs.

The table can answer membership only while its construction and lookups use
Gerbil's standard identity-table methods. A focus callback can change those
methods, so the builder checks again before using the table. Once the check
fails, membership uses the owned list for the rest of that builder's life.
The original focus operations still run.

This family-wide check does not decide where a component equation reads
its dependencies. A dependency in the current SCC uses the current
fixed-point input. An external dependency uses the closed predecessor.
The family index also contains keys outside that SCC. The first-use SCC
index experiment was dropped after the sparse cold lookup at one million
members went from 4.6830 to 180.0730 ms CPU.
