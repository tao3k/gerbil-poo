#+title: Ordered Graph roster admission: proof and implementation gates

* Status and scope

This is a mathematical design, not an adopted Scheme optimization.
[[file:graph-roster.lean][Lean]] proves ordered roster/support equivalence;
[[file:graph-roster.sysml][SysML]] records the implementation obligations.
No new loader, cache, API, validator or evaluator is introduced. Production
remains on the existing two-pass path until ALL gates below are satisfied.

The domain K denotes validated Gerbil symbol identities. =keys!= still owns
proper-list/symbol validation and its error payload. For the existing
=delete-duplicates/hash= call with =from-end?: #t=, the admitted order retains
the first occurrence. The model permits duplicates and arbitrary initial
membership; it is not limited to a unique generated fixture.

* Proven mathematical contract

| Lean theorem | Guarantee | Implementation boundary |
|--------------+-----------+-------------------------|
| same_order | One pass preserves ordered first occurrences | keys! normalization |
| final_membership | Final membership is old domain union input | index-keys support |
| firsts_membership | Returned keys were input and previously absent | normalization |
| firsts_unique | Returned roster has no duplicates | schedule-owned roster |
| one_pass_exact | Ordered roster AND support equal two passes | proposed fusion |
| checked_exact | Reuse the same validation result, including errors | validation stays first |
| continuation_exact | Equal results preserve any pure continuation | no callback effects inferred |
| mark_other | A different key's membership is unchanged | functional state only |
| with_trace_exact | Data plus equal effect trace are equal | trace equality must be established |
| trace_mismatch_rejects | Different effect traces disallow full equivalence | negative specification |

The continuation may produce a failure value; this is not a proof that an
effectful Scheme callback has been checked. Snapshot ownership of a mutable
table is also not implied by a functional map. There is no axiom asserting
Scheme/Gerbil correctness, constant-time hashing, GC bounds or milliseconds.

* Actual-callee diagnosis

The optional =cold-owned-phases-test= calls the current private production
callees in =schedule-owned= order, placing measurements BETWEEN calls. It
does not install an author observer or alter production authentication. The
fixture supplies 100K/1M symbol names, no code/base bindings and no edges;
this is neither real Module admission nor business .get. Each size uses
=complete staged staged complete=, natural GC, with order/domain/empty-row
checks outside timing. The staged execution adds measurement boundaries.

independent phase medians or present this as a full Module EVAL result.

The fixed diagnostic exits naturally with MODULE-OK, HARNESS-OK and final OK:

1,090,863,104 bytes. An earlier diagnostic failed because a local =values=
binding shadowed the multiple-values procedure; its failure is retained in
local artifacts and excluded from passing evidence. Raw logs are not committed.

* Before adopting Scheme fusion

1. Establish native table semantics for validated symbols, including absent,
   false and duplicate observations. Do not conflate capacity with membership.
2. Resolve constructor/random-source effects. The current normalization and
   support passes construct separate native tables; removing one changes the
   constructor trace. The pure equivalence proof does NOT license that change.
3. Keep validation and every expansion/author-callback check in order. Do not
   reuse evidence across callbacks or skip original row captures.
4. Prove mutable snapshot ownership for any reused table. Preserve old
   snapshots, order-copy isolation and first refusal on invalid bindings.
5. Test matched faults plus native differential cold/warm/revision behavior
   through existing heap-fenced Just entrypoints; compare complete CPU, wall,
   GC and actual scan/allocation work, retaining unfavorable controls.
