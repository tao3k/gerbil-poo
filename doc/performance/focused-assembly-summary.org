* Implementation and related TODO closure
prepare-focused / prepare-focused-inheritance compose local fragments FIRST,
then perform one outer lens write per nonempty raw stage. focus-protocol retains
the per-fragment reference semantics. Both reuse native C3, existing Lens,
method wrappers, demand cooking and FUN observations. No second object engine,
manual slot-cache implementation or mutable global result cache is introduced.
Empty fragments return the exact inherited carrier without touching the lens.

Previously each of four local fragments performed a persistent POO outer write;
subsequent getters prepare that new object's precedence/slot caches. Two stages
therefore traverse eight outer versions. Focusing the assembled local program
reduces logical writes to two, retaining all eight LOCAL fragment applications.
This closes a concrete TODO path for direct local component construction; local
fragment assembly still runs, and unrelated projection elimination remains open.

The nested billing factory now selects focused assembly. prepare-nested-unfused
retains the previous current-code path as the direct native control. An additional
billing envelope composes TWO outer slot lenses, independent approval and tenant
metadata, the shared C3 diamond, repeated cooked-self demands and existing sum
methods. It produces 45/3/billing/eu/true. Tenant revision yields us; refusal
uses the current configuration and leaves the old binding valid. Native tests
cover both paths, independent audits, empty assembly and 8→2 writes.

focusDelayed_assemble prove fusion under these laws; prepareFocused_observe
covers every finite depth/base/seed. focusDelayed_lensGen connects this lift

proves the logical surrounding-write bound. Pair-carrier examples discharge
actual laws and retain 39/3/service metadata under arbitrary revised frames.

Native POO objects with different .cc ancestry are NOT literally identical.
Correspondence uses their immutable, extensional selector observations and the
specified functional lens domain. Callbacks inspecting identity, raw ancestry,
mutation or arbitrary host effects must use the general path; native callbacks
are not automatically checked for these laws. Total Lean functions do not prove
Scheme callback termination or exception-effect equivalence. No Scheme module
reads a Lean checkout; no native compiler/runtime verification is claimed.
Logical writes/operation budgets are separate from measured bytes/time/GC.

* Fair native study
Three complete runs were fixed BEFORE measurement, each 576 children: twelve
scenarios, natural/collected, direct pair plus two A/A controls, four balanced
ABBA rounds. One setup creates immutable fused/unfused snapshots and both actions;
each A/A duplicate is the EXACT same procedure. Every child warms all four
controls in fixed order; the driver admits source/binary identity, exact coverage,
EOF, signed GC-free allocation and prefix statistics. No build/test overlapped.
Compiler/study caps 90s, each child20s/1GiB; caps were not widened.

The baseline is the CURRENT unfused demand-cooked/shared-self path, not the older
eager implementation. nested-history adds exactly 64 complete unfused observations
before all warmups/timing, identically per child; natural does not force GC.
Collected uses the shared driver's one pre-timing collection. History comparisons
show sensitivity under a declared perturbation, not identical heaps or causal GC
proof. All three receipts remain separate, with no selected/pool-adjusted run.

nested includes construction, cooking and all price/rebate/service observations.
construction excludes final cooking but checks real raw slots/cache/audit; hook
is one stage of that same work. cooking uses a common already-constructed raw
carrier and identical action on BOTH sides. binding uses the same fused snapshot
and changes prebound versus one-off observation only. Cold includes C3-cached
declaration capture, compilation, binding, construction and complete observation;
initial graph/module initialization remains outside it. Revision includes fresh
configuration preparation/binding; envelope uses an already compiled snapshot.
Semantic oracles are inside timings on both sides; no discarded result is timed.
Allocation scenarios fix ONE operation; small CPU samples include timer noise.
