#+title: macOS Scheme build preparation and bounded reuse

* Measurement boundary
These receipts use the macOS ARM64 precompiled Gerbil release 1cfb032 / Gambit
ea114fc, Homebrew package patch618d76f9eb72, GCC 16.2.0 and macOS 26.6.1.
They are Scheme build measurements. Other hosts and proof-checker timings are not
controls for them. The package does not build Gerbil or introduce Bazel.

GERBIL_BUILD_CORES=12 was observed as twelve concurrent GSC descendants, rather
than inferred from an environment variable. This limits backend workers; it does
not parallelize every import or macro-expansion operation in one interpreter.

The released std/make first imports root modules to prepare its completion table,
then starts dependency coordinators and workers. Its import mutex serializes
imports. Library interfaces can avoid repeated source expansion, but a complete
source build still has mandatory expansion and generated-code costs.

The four-batch receipt is not a cold full build. Its batch durations were 125.741,
125.407, 89.492 and 207.525 seconds; two batches run concurrently. Corresponding
interpreter GC CPU seconds were 3.538, 3.290, 2.089 and 7.461. GC CPU is neither
whole-process-tree CPU nor GC wall time. The whole duration includes startup,
termination and the parent. Independent component durations must not be added
and reported as a measured complete build.

The original bare build entry did not explicitly cap the compiler interpreter's
heap. The monolithic 1 GiB refusals diagnose behavior under the explicit guard;
they do not establish the cause of an older unbounded seven-minute run. Tests
retain their existing 1 GiB/default heap and 90/300-second bounds. Compiler stages
now receive that configured interpreter bound, a 300-second stage deadline and
an owned process group. The complete build retains the 20-minute ceiling.
These are interpreter bounds, not a claimed aggregate RSS cap for GCC/GSC children.

* Current build protocol
The build entry uses the standard defbuild-script compile/clean/spec/meta
protocol. std/make owns dependency and incremental decisions; explicit library,
tests and batch arguments select only the project inventory and output location.
GERBIL_PATH, GERBIL_BUILD_CORES and GERBIL_BUILD_VERBOSE are standard Gerbil
settings. The extra project build-selection and observation environment switches
have been removed.

The outer resource boundary retains heap/deadline/process-group cleanup and a
short-lived SSI-first test view. No local byte-generation cache, compiler
fingerprint, source-generation receipt, producer lock or custom cleanup remains.
CI source admission stays separate, using the existing Actions artifacts and
complete semantic checks.

* Historical measurement boundary
The remaining receipts describe the source revisions and diagnostics named in
each section. Their local cache and command/import observers were experimental
and have been removed in favor of the standard build protocol. Historical warm
cache results do not describe the current standard incremental path. No complete
cold-build speedup is established by those receipts.

* Reproduction and attribution
Use an empty GERBIL_PATH outside the checkout for a cold run; repeat the exact
command with the same path for a warm run. Keep the release and worker count
fixed and retain /usr/bin/time -l output, standard make progress and exit status.
The driver emits actual stage starts/ends and source-admitted cache hits. Full
logs, traces, compiler artifacts and archives remain outside Git.

The historical t/build-benchmark.ss collector recorded macOS process parentage and
timestamped output in Scheme data. Sampling runs diagnose worker overlap;
unwrapped runs qualify wall time. Sampling cannot identify very short processes
or prove continuous worker occupancy. A GSC interval includes its C compiler and
linker descendants. GCC -pipe permits C compilation and assembly to overlap;
clang -cc1as is assembly, not a linker. Inclusive intervals must be unioned rather
than blindly added. Import spans combine resolution, interface reading and
expansion; they must not be relabeled pure macro-expansion time.

The bounded-batch completion receipt establishes feasibility, not an end-to-end
speedup ratio. Complete cold/warm measurements and exact-revision CI are required
before publishing a complete-workflow performance claim.

* First complete guarded candidate
The first complete candidate used the uninstrumented build entry and empty output:
759.99 seconds wall (576.08 user, 116.14 system), exit 0, all 304 source roots.
Shared cleanup took 16.356 seconds, shared compilation 237.398 seconds, and the
four test batches 276.905, 280.216, 104.793 and 207.213 seconds. This is not a
qualified cold-build speedup. The earlier 347.96-second test-only diagnostic used
a package directory containing previously compiled test products; it is not a
matched isolated-shared-library control for the complete candidate.

Repeating the exact candidate with its admitted complete byte generation took
11.33 seconds wall (2.46 user, 0.79 system), exit 0, with no compiler stage started.
The first complete single-process test run hit its unchanged 300-second deadline
(305.54 seconds including forced termination), after 57 module completions. Its
separate warm-loading control passed all 121 modules in 170.38 seconds (25.24 user,
2.70 system). The cold refusal remains an open gate, not a warm pass.

A two-second sample of the cold test startup contained 183/189 observations in
dlopen -> Loader::mapSegments -> fcntl. This is a sampled loader wait, not a claim
that 96.8% of the entire test duration has that cause. Generated bundles had
linker-generated ad-hoc signatures and a provenance attribute. Apple dyld's
[[https://github.com/apple-oss-distributions/dyld/blob/main/dyld/Loader.cpp][Loader implementation]] registers signatures and checks library validity in this
path. The sample alone does not identify which fcntl operation or policy caused
the delay. Source expansion, code generation and GC must not absorb that residual
under an invented phase label.

* Inventory dependency reduction
The inventory module now contains only enumeration and batching. Source hashing
stays in the existing artifact protocol; the matrix command uses standard JSON
serialization in t/test-matrix.ss. The checked twenty groups and 121 test roots
are unchanged. No handwritten JSON serializer or alternate inventory was added.

A before/after/after/before metadata control on this macOS release, using empty
package paths, measured 19.52 / 4.99 / 6.68 / 20.41 seconds. DYLD_PRINT_LIBRARIES
reported 283 bundle loads before and 100 after. This qualifies metadata startup
only; it is not a complete-build speedup ratio.

A separate startup sample contained 817/819 observations under dlopen, including
778 under dyld notifyDebuggerLoad. Unlike the earlier fcntl sample, this window
shows image-registration work. Neither sample establishes whole-run attribution.
Mapping all 431 generated project bundles with twelve bounded helper processes
took 168.81 seconds. This standalone preflight was rejected: moving that work to
another stage does not establish a shorter workflow. Signing changes were also
not adopted.

* Phase observation
The former POO_BUILD_IMPORT_TRACE selected the public expander-import observer. Its Scheme
records include wall intervals, interpreter CPU and interpreter GC CPU. The
separate t/build-command.ss diagnostic executable records GSC, GCC and GCC
-wrapper subprocess intervals using /usr/bin/time -p. Standard process ports
inherit stdin/stdout, retaining GCC -pipe. Compiler diagnostics stream once;
only three stderr lines are delayed to parse the time footer. Missing or invalid
timing fields refuse metric admission, not the underlying command's exit status.

The command observer is macOS-only; its pure timing parser has regression
controls on every CI platform. Raw traces, diagnostic executables and generated
products remain outside Git. Instrumented runs are diagnostic observations, not
unwrapped wall-time controls. Nested command intervals and pipelined C/assembly
must be unioned; import resolution/expansion and unobserved scheduler/parent work
must remain explicitly distinguished rather than assigning the residual to GC.

aggregate process-tree RSS limits, and the outer time command is not a complete

Full diagnostic data, source copies and binaries remain outside Git.

The 250 ms sampler misses short-lived commands; a single assembler observation
does not mean one assembly job or zero assembly time. These first/last windows

later jobs. Exact macro-only and scheduler-only wall totals, and a successful
complete current-revision macOS cold build, remain open acceptance items. The
command observer provides finer boundaries only on runs that actually reach
those commands; an interrupted prepass cannot produce valid backend totals.

* Admitted CI consumer entry
The single-process CI job previously called =just build test-program=, ran the
complete suite, and then called the standalone =just benchmark-collections=.
That standalone recipe correctly owns library and executable preparation for an
ordinary checkout. Re-entering it after artifact admission repeated both stages.
In run 39889131748 the benchmark step recompiled shared modules for 88.37 seconds,
then rebuilt/relinked the executable for 88.90 seconds; the workload compilation
was 5.93 seconds and the actual study 1.51 seconds. These are Linux CI receipts,
not macOS or proof-checker measurements.

Gerbil's released =std/make= tests source/output/dependency timestamps, including
SSI and static Scheme outputs. CI Actions cache admission instead checks complete
source keys, compiler-output identity, group membership and the current revision.
An admitted artifact is not a warm producer filesystem with its original freshness
relationships. In this run the second library entry issued 141 shared compilation
commands, followed by the executable and workload compilation. It was real work,
not merely the time taken to enumerate dependencies.

The job now retains the existing current-revision and complete disjoint-group
admission, then times one =just _check-collections 2 1 4= entry. Standard
=defbuild-script= constructs the consumer once. The entry runs the entire bounded
single-process suite, compiles the collection workload through the existing
standard consumer target, and executes every original phase/control. Public
=benchmark-collections= still owns normal library/executable preparation; both
routes share the identical =_run-collections= command. No new build-selection
environment variable, timestamp rewriting, dependency resolver or cache format
is introduced. Existing Actions caches remain the owners of cross-job reuse.

The recipe-graph regression asks Just itself to resolve both routes. It checks
one executable preparation in the admitted entry, library plus executable in
the standalone entry, one workload compilation and one full study in each, and
the original bounded whole-suite invocation. Existing stale/missing/extra-group
and revision controls remain active. The interpreter heap is still 1 GiB;
compiler/test stages retain their original 300/90-second deadlines, process-group
cleanup and complete test inventory. The job still has its ten-minute limit.

execute 128 modules, 1,250 cases (including the new graph regression), and all
111 study summaries with =COLLECTION-PAIRED-OK=. Standard Bash =time -p= wraps
the complete entry, including Just/compiler startup, dependency preparation,
whole-suite execution and the study; inner workload time is not substituted.

| Order | Entry | Complete wall seconds |

| B1 | admitted single entry | 25.27 |
| B2 | admitted single entry | 25.97 |

Paired savings are 16.57 and 12.24 seconds. This is a two-pair warm local control,

Raw full logs remain outside Git; no full datasets or archives are committed.

* Reusing the checked test executable
Run 39891329319 measured 148.65 seconds for the complete admitted entry, including
117.19 seconds in =test-program=. The executable backend was entered about four
seconds after construction began. The remaining backend interval includes Gambit
C generation, per-module static-object compilation and final linkage; the old
verbosity does not isolate each subinterval. The installed separate-compilation
driver's Linux branch queues this executable phase as one task and walks its
object jobs serially. A larger make worker budget alone does not split that task.
Cold-run standard =GERBIL_BUILD_VERBOSE=9 now exposes the actual backend commands.

The existing Actions cache covered library and disjoint test-group outputs but
excluded =bin/test-program=. The single-process job now caches that standard
Gerbil executable after successful full acceptance. Its immutable key binds the
existing shared source key, exact compiled library bytes, and ordered test-file
inventory. The source key already binds release identity, OS/architecture and
host compiler identity. The existing =setup-gerbil= action now computes that host
identity once per job, including compiler, linker, libc and pkg-config OpenSSL
version/flags. Producer, test compilers and executable consumer use that same
output instead of separate implementations or selection environment switches.

Test bodies remain bound by each group's existing complete source digest and
current-run revision admission. A body-only edit preserves the executable's file
inventory key while invalidating its group source key. Adding a test changes the
inventory key; a missing declared test refuses before cache lookup. Regressions
exercise these cases on a temporary complete source inventory, and ask Just to
resolve miss, hit and standalone recipe graphs. A hit still runs the original
whole-suite harness and every collection study phase with the same limits.

A cold miss still constructs and checks the executable through =defbuild-script=.
A hit checks executable permissions and uses =_check-linked-collections= after
all source/compiler/group admission. The executable also retains its runtime
inventory and linked-library checks. Standard Actions cache owns transfer and
reuse; no second object scheduler or custom on-disk cache protocol is introduced.
A genuinely new compiled library requires a new executable. Cache restoration,
miss construction, full execution and cache save are distinct measured intervals.
