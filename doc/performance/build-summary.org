#+title: Standard build, test preparation and recovery

* Entrypoints and ownership

Use the existing package declarations and native Gerbil commands:

| Task | Entrypoint | Declaration owner |
|------+------------+-------------------|
| Production libraries | =just build-core= | =build.ss= |
| One semantic suite | =just test-file t/<group>/<suite>-test.ss= | Gerbil test |
| One semantic group | =just test-group <group>= | Existing Just queue |
| Shared executable example | =just build-shared= | representation-startup package |
| Benchmark package | =just build-benchmarks <group>= | Its existing build.ss |
| Complete acceptance | =just check= | Existing public build/test/study entries |

Gerbil and std/make own imports, freshness and declared outputs. Just supplies
standard arguments, queueing and process bounds. Do not add another scanner,
manifest, runner or compilation cache. Optional linked programs keep their own
package declarations rather than extending default production installation.

* Compiler and concurrency policy

Production compiler options and included inputs belong in =build.ss=; test
package options belong in =t/build.ss=. Keep compared arms on the same toolchain
and options. Rebuild affected consumers when changed interfaces may have inlined
field accessors; a matching public name alone does not establish ABI identity.

Use =GERBIL_BUILD_CORES= through the existing entrypoint. Scheme heap limits do
not bound the external C compiler's process-tree memory. Keep the applicable
compiler, child-process, complete-study and memory bounds distinct. A code-
generation change must be qualified separately from an algorithm speed claim.
Use the current Just/workflow declarations as the authority for exact limits;
historical machine-specific values are not configuration defaults.

* Cache ownership and recovery

A completed native target can be reused only through its original declaration
and current inputs. A successful interface file does not prove that its backend
job completed. The existing build entry refuses outstanding compiler locks;
do not remove locks while their compiler is active.

After an interrupted or refused build, retain its diagnostics and use native
=gerbil clean= or =gxpkg clean= for the owning package/prefix before rebuilding.
Do not manually delete selected .ssi/.o1 files, transplant old interfaces, or
use =gxpkg uninstall= to repair a package workspace. Restore standard declaration
ownership rather than teaching downstream code about compiler artifacts.

* Timing interpretation

Separate source expansion, C generation, C compilation, linking, first import,
first demand, later demand, test execution and natural exit. Nested measurements
cannot be added to their enclosing interval. A passed harness marker is not
process completion; retain the exit status and the applicable watchdog result.

Compare the same platform and build/cache condition. A partial retry cannot be
compared with an empty-prefix build as a cold-build gain. Wall-minus-CPU is a
residual, not proof of a particular linker or OS bottleneck. Keep failed and
regressing samples in local output or CI artifacts. Version only a concise
matrix with the implementation it qualifies, not per-run transcripts.

The benchmark output policy is [[file:results.org][results.org]]. Historical run narratives
remain available in Git history and local evidence; they are not current
acceptance for changed source.
