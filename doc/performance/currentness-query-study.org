#+title: Currentness query study: retain the baseline
#+date: 2026-11-16

* Decision

Neither of two native Slot-currentness variants meets the original complete
workload gates. Both are withdrawn. Passing semantic tests is necessary but
does not establish a performance improvement. Core stock remains in place.

* Actual SourceRole authentication

The original Core =207524f= SourceRole workload uses three datums, with stock
batch admission and three individual Generic calls. A frozen fixture adapts
only the MOP spelling and std/test wrapper; it is not an alternate evaluator.
Diagnostics run the original business actions and count actual issuer calls
by record identity and phase. They are not CPU comparison samples.

At POO =8371d25=, EACH individual Generic call reports:

| Phase | Issuer calls | Unique read identities | Repeated inside phase |
|-------+--------------+------------------------+-----------------------|
| First Generic admission | 61 | 61 | 0 |
| Direct-group currentness | 152 | 152 | 0 |

The 61 admission identities also occur in the group. They are not a proven
elision opportunity: ordinary getters and policy checks intervene. The
current scheme deliberately reauthenticates after those operations. Earlier
diagnostics confirm all 768 sampled Generic calls actually use direct entry;
carrier allocation is not an unconnected production path.

Aggregating three datums produces 183/456 calls over 61/152 identities.
Do not misreport that aggregation as three redundant checks within ONE call.
Likewise, the original stock arm batches the datums: its difference from
Generic includes different admission boundaries, not dispatch alone.

* Candidates and semantic gate

The existing direct-group checker already borrows native vector fields
after receiver-route admission. The batch sweep uses ordinary HashTable
queries. We tested reusing the native query there, without removing the
per-record issuer check or independent callback-return sweep.

- Borrowed view: store the existing receiver-local query closure in the
  batch sweep's existing position vector, constructing it fresh per sweep.
- Immediate fields: keep the existing Boolean position vector; extract
  admitted fields per read, using one shared expression for native Slot
  semantics instead of constructing another query closure.

Both retain bootstrap's ordinary live path, false/missing distinctions,
foreign-route fallback, key/route/refusal order and fresh views after effects.
The first uses frozen =8371d25=; the second uses =eeeb4ca=, including the
new malformed-precedence control. Baseline and candidate within each
comparison use the same respective native CLOS/MOP cohort.

Both passed the same 117 native cases and naturally exited: issued reads,
sizing effects, read projection, Graph order repair, CLOS evolution and
method combinations. The tests include a cache fill without a revision change
and record mutation during extensible index sizing. No assertion was removed.

[[https://github.com/tao3k/lean-poo/commit/da8be97][Lean da8be97]] adds =LeanPoo/Object/BorrowedReadCurrentness.lean= and
proves conditional field equivalence, ordered guard preservation and separate
return views. Its same-window premise covers read membership and cells as
well as revision/instance. It does not certify malformed native memory,
external callbacks, performance or allocation. Org and SysML state this limit.

Use the existing compiled =benchmarks/graph-capture-test.ss=, retaining the

First capture regresses in both orders for both candidates. Borrowed-view
later CPU benefits from a different GC placement (one collection vs two);
this is not a first-capture improvement. Whole-capture allocation is =#f=
because GC occurs. Do not manufacture a full allocation total from it.

No-GC attributed batch-currentness intervals expose additional allocation:
borrowed baseline 2,688,816 bytes vs 4,768,608--5,686,128 bytes;
immediate baseline 3,606,336 vs 5,206,176 bytes. These locate the regression,
not a performance result for the whole capture. Native multiple-value
transport remains an allocation cost even after removing new closures.

Guarded process-tree footprint: borrowed baseline 484,917,248--486,391,808
bytes vs candidate 476,184,576--480,231,424; immediate baseline
481,705,984--481,853,440 vs candidate 492,879,872--499,482,624.
Lower RSS in one experiment does not override its slower first capture.

* Reproduction and next action

Gerbil =2591dcd=, Gambit =dcd677c=; identical =gxc -O -cc-options -O2=.
Compile one large C target at a time under the existing 180-second/4-GiB
resource guard. No host-load wait, prewarm or enlarged budget is used.
Both arms load the same explicit compiled benchmark .ssi; only the object
module under comparison changes. Full logs, receipts, frozen source and
diagnostic fixtures are retained under ignored =.build/graph-capture/=:
=call-auth-*=, =borrowed-graph-*=, =direct-graph-*= and
=borrowed-source-role-*=. Logs are not Git payload.

The native semantic gate passes; the performance gate fails. No Scheme
optimization from this study is promoted. Future work should return to the
previously attributed cold SlotSpec/value-store preparation, rather than
retry these query transports or assume that the issuance registry dominates.
Keep first/later capture and complete SourceRole acceptance separate.
