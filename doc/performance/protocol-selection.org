#+TITLE: Effect-framed protocol selection during method installation
#+DATE: 2026-11-10

* Shared source preparation: dependency boundary

The structural index implementation now lives in =support/index.ss=.
=generalized-graph.ss= imports and reexports its same five operations rather
than owning another implementation. Its immutable base and path-copied sparse
tree preserve old snapshots, false payloads and live projection behavior.
This removes the dependency cycle that prevented =object.ss= from reusing it.
It does not yet implement source custody or sparse receiver preparation.

The one live read issuer allocation also moves below =object.ss= into
=read-route.ss=. Object keeps its existing bindings. Lower source code can
authenticate against the same authority; the writer remains private and no
second weak registry is allocated. Independent factories cannot authenticate
its records. New source-certificate kinds still require separate admission
from ordinary receiver value reads before that integration is enabled.

The new index control lives in the existing Graph repair suite. It checks
fork/base identity, false versus missing, empty values, projection call counts
and old-root isolation. Removing only the sparse-tree copy fails both that
control and the original SCC merge/differential controls with exit 42.
The issued-read suite retains 29 Cases and checks lower/Object authority,
foreign-factory refusal, private writer exports, original refusal order and
callback-return validation. These are semantic controls, not latency evidence.

The current issued-read suite has 32 Cases. Its existing layout and checkpoint
Cases also require a fresh return check after a callback changes the same
Gerbil class's field map. Initial class/layout admission cannot authorize the
return route. A second control captures a cache miss, then demands a lazy
slot whose value is =#f=. The logical receiver revision and payload stay
unchanged, but the miss record must become stale: missing and present-false
are different observations. The newly recorded present-false read remains
valid. No additional Case, runner or runtime cache is introduced.

These are Scheme correspondence obligations for any interval-sharing model:
the post-callback state owns its own live checks. Layout sharing and entry
issuance reuse must stay inside their pure intervals. Payload truthiness
cannot replace presence, and a successful entry check cannot survive an
arbitrary callback. This test-only extension changes no runtime algorithm
and claims no new public Lean theorem or performance improvement.

The complete first-demand path still prepares all methods and value-directory
keys. No first-business speedup or downstream pin promotion follows from this
dependency refactor. Compiler-owned source capture and demanded binding remain
the next implementation owner.

* Change and contract

The final =compute-slot-funs!= pass previously selected an inherited protocol
for each surviving method. With =P= ancestors and =S= methods, absence can
require =P*S= ancestor visits. For multiple methods, the candidate checks the
actual symbolic write route and selects absence once. It retains the same
enumeration, callable checks, writes and payload capture. Zero/single-method
objects retain per-method selection. A present protocol or changed route
retains dynamic selection, including effects between writes.

The route guard checks the actual selected =set!= procedure, wrapper/backend
classes, symbolic hash, equality test and absence of a lock. Rehash consults
backend hash/test, so a matching write procedure alone is insufficient.
It never calls replaced functions. This uses the supported serial runtime;
it does not authenticate arbitrary FFI writes or concurrent mutation.

[[https://github.com/tao3k/lean-poo/commit/55ed9c08899f3de4d990b88f937f18bd5e89cebe][LeanPoo SlotPreparation]] proves ordered-result/error/final-state equivalence
under the write frame, and gives a counterexample to initial absence alone.
Its count law covers protocol visits, not total native CPU work.
The representation/mutation discussion in [[https://fare.tunes.org/files/cs/poof.pdf][POOF]] motivates sharing pure
structure; it does not supply this runtime guard or a latency bound.

* Ordered contribution index prerequisite

Point preparation needs every contribution at the selected name, in source
order. =prototype-map-ref= returns the first entry and cannot implement that
fold. The new =prototype-map-fold-key= borrows the existing private name and
ordinal indexes. Compact maps scan at most eight entries; tree maps perform
one name lookup and one ordinal lookup per matching contribution. The first
ordinal precedes the reversed duplicate tail. There is no second index or
receiver cache, and payload references remain opaque.

LeanPoo =Object.OrderedContributions= proves the selected bucket and method
fold equal the chronological source fold, with concrete sibling insertion
and native ordinal-spine laws. This is an index law for supplied rows, not
a source issuer or a machine-level Scheme refinement proof. Defaults,
admission failures, raw SlotSpec exposure and effects retain their own checks.

Native representation qualification passed 86 Cases. Removing only the
duplicate-tail reversal failed both chronology and callback-refusal controls
with exit 42. Restoration passed the same 85 Cases. The controls compare
complete traversal against selected folds across both policies, small/large
maps, duplicate names, symbol identity, false/Function payloads, replacement,
removal/reinsertion, retained snapshots and actual inherited method results.
An explicit raw malformed-sibling control also refuses a normal selected
read after successful keyed projection; the primitive cannot authorize
bypassing source preparation.

* Source and evidence ownership before shared preparation

A source/clone view is not its raw storage owner. Unchanged SlotSpecs can be
shared by several views, and =.cc= replaces the first indexed contribution,
retaining later contributions to the same key. A reflected raw write affects
future captures through all those aliases; old prepared methods keep their
captured payloads. The extended representation/observation entry passed 93
Cases through the original tree/compact paths.

=LeanPoo.Object.SourceViews= derives registration multiplicity from actual
rows, local replacement/batch deltas and the existing old-inverse row-frame
theorem. Counts alone do not authenticate distinct view ordinals. Pending
capture rejection derives exposure drift from the actual registered frontier
and uses the existing publication check. Native source custody and indexed
plan sharing remain open; these laws do not make the point primitive a full
preparation implementation.

The structural-name issuer also had a concrete ownership defect. Its alleged
canonical list still aliased the producer's mutable name cache. Editing that
cache and the record's raw presentation together authenticated a changed
payload. The new control fails with exit 42 against freshly compiled exact
=81447d16= source. Native issuance now owns a private canonical copy, separate
from both producer and presentation. Restoring the original presentation
restores issuance; receiver/route currentness remains independently checked.

The fix passed all 29 issued-read Cases through source and optimized AOT
entrypoints, plus the 93 representation/observation and 26 inheritance-hook
Cases. The four =SlotObservation.NameCapture= laws are axiom-free; the complete
local Lean root has 406 jobs. Ordinary opaque business values keep their
identities: copying applies to structural =(names)= evidence, not a user slot
named =names=. No cache, loader or new action is added.

This is a correctness repair, not a first-demand speedup. The standalone
deferred-method backend and default hash-value experiment were not selected
and are not part of this change. Whole-source preparation, the historical
seconds-scale first business demand, Core 10K/180-second/4-GiB and downstream
acceptance remain separate open gates.

* Writer layout qualification and rejected method snapshot

The native symbolic-writer guard must check the current =object= and =set!=
field offsets before invoking pinned accessors. Keeping the same wrapper class
does not freeze its mutable field map. The existing inheritance-hook control
now moves each mapping separately and restores the shared map before asserting
refusal. =LeanPoo.Object.FixedFieldLayout= states this live-layout premise; this
is a correctness correction, without a performance claim.

The same final regression fails the old native writer guard with exit 42.
The corrected native runtime passes 26 inheritance-hook and 32 issued-read
Cases. Graph validation passes 42 algorithm/order Cases plus 10 publication
Cases separately: the first aggregate failed to import an unprepared example,
so that preparation failure is retained and only the unexecuted module rerun.
This is not a successful single-process aggregate or a Core capacity result.

A separate operation-local method-snapshot candidate was rejected. Under the
existing C =-O2= object-scale workload, the baseline/candidate/candidate/baseline
CPU times for 5,000 clone/read operations at 256 slots and 32 layers were
1.479136 / 1.492456 / 1.348273 / 1.220414 seconds. The candidate did not show
stable CPU improvement; fewer collections did not establish a latency gain.
All four completed arms and the failed native rehash-order fault are retained
as local artifacts. No snapshot helper, method-table reuse or write elision is
adopted. The whole-source preparation and 10K acceptance gaps remain open.
