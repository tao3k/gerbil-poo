#+title: Standard Gerbil test loading and completion

* Supported entry

Run semantic suites through =gerbil test= and the existing Just recipes.
=just test-file= selects one suite; =just test-group= selects its declared group.
The complete entry uses the existing test queue. Keep the explicit single-
process entry for detecting cross-suite state, rather than adding another
aggregate runner or silently replacing the default scheduling policy.

Production libraries, test packages and linked examples keep their original
build declarations. Match relevant dependency interfaces and compiled consumers
before attributing first-load cost to the object system. Imported modules and
native images are a preparation dimension, not a substitute for business work.

* Acceptance and failure

Require discovered cases, successful case/module/harness markers and natural
process exit. A marker emitted before a timeout, abnormal exit or failed cleanup
does not pass. Preserve callback, mutation and negative controls; do not hide a
functional failure by rerunning only the successful subset.

Use the current recipe/workflow bounds for the selected entry. Distinguish
compiler preparation, child test, idle detection, total execution and memory
limits. An observation timeout does not establish that the child has stopped;
recheck its existing handle before restarting it.

* Measurements and output

Measure import/preparation, execution and exit separately on the same platform.
Do not infer OS-specific attribution from wall time alone or advertise a smaller
artifact inventory as a runtime speedup. Use the cache and timing rules in
[[file:build-summary.org][build-summary.org]] and the output policy in [[file:results.org][results.org]].

Raw stdout, manifests, sampled process records and run-specific counts remain
in ignored output or CI artifacts. Current acceptance refers to the actual
published revision and its completed checks, not an older recorded local run.
