* Correspondence and implementation
This advances generalized-protocol future work, not completion of the whole paper.
Racket pin: poof 9affa8fbbb4f12cbd98cb97f8b8b84474fc39429. fix--1 at
poof.scrbl 2355–2374 retains shared final-self construction; the memo sketch at
1906–1940 is commented experimental material. The bounded/certified machine is
an explicit Lean extension, not code claimed to occur in that Racket section.

recursive.ss uses existing prototype composition and native FUN .ap/.bind/.map
for explicit values, source errors and final-self requests. Source observation
solve depth is different from Cached resolve/evaluate machine depth, which also
bounds continuations. A source pending result is not a divergence decision.
recursive-cache.ss uses a private standard equal-key table; a writing run copies
it once and inserts only completed owned receipts. Cache owner is exact immutable
Generator descriptor identity. Code changes must start a new memo; no certificate
retagging or result-based source equality is allowed. Machine cycle/exhaustion
returns the exact original memo, discarding all tentative children and counters.
Completed explicit source errors are cached like values.

recursive-handling.ss resolves the CURRENT POO registry/signature/native Types
before memo lookup. Input/schema/signature refusal retains the exact session and
unknown reuse. Direct reuse reports ROOT membership, not nested child hits. Every
completed value still passes current output admission; output refusal and completed
source errors retain completed memo. RequestAction. composes retained-state calls
through FUN, and ordered batches stop at the first refusal without losing its
completed state. Composed result reuse metadata can be unknown.

examples/recursive-catalog.ss composes inherited head override, nested shared
chain/callback requests, current output ceilings, callback removal, partial batch
resume and typed multi-dispatch with an unchanged business ledger. Native function
references use symbols in this concrete example; this is not a general port of
Lean Dynamic descriptor factories, wire codecs or dependent evidence.

examples/cyclic-access.ss now has start-attested/revise-attested/rebase-attested.
An actual Boolean evaluation receipt seeds the original ten positive equations;
least re-solving and existing joint publication remain authoritative. Completed
false revokes release. Any recursive/source/publication refusal retains the exact
old public wrapper AND old memo. Rebase explicitly discards memo under new code.
Existing literal-seed functions remain low-level construction primitives.

* Proof and verification boundary
Existing Recursive / RecursiveCacheSemantics prove finite observation agreement,
completed receipt soundness, monotonic source observations and the semantic cycle
claim. RecursiveHandling proves current admission and retained batch state;
CyclicAccess observed_source/revoked connects actual evaluation to least closure.
New runCertified_hit proves exact receipt/entry/miss/step preservation and one extra
hit at positive budget; runCertified_zero refuses even a warm root at zero budget.
RecursiveSession.call_warm_current retains current registry admission after a hit.
RecursiveMemoCosts.covered charges common admission on BOTH sides and requires
source savings to pay setup and excess GC. Its example prices are illustrative,
not native timing claims or constants embedded in Scheme.

Native receipts are sealed runtime provenance, not serialized Lean proofs. The
correspondence assumes immutable/extensional program, keys/results, pure callbacks
and locally terminating generator/continuation code. Arbitrary Scheme callbacks can
hang outside the machine's depth control. Fuel is not a total work or memory quota;
cycle paths are operational diagnostics, not kernel divergence proofs in Scheme.
No compiler, runtime, collector or arbitrary host termination validation is claimed.
The package/tests/benchmarks require no Lean checkout.
