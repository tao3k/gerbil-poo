#+title: Retained SCC direction: changed-row admission and explicit output

* Candidate: preserve nontrivial components by exact edge differences

The existing predecessor owner index can certify another local case. Every
effective inserted edge must stay inside one old SCC. Every effective deleted
edge must cross old SCCs or be a self edge. Then the SCC relation is unchanged:
an internal path retains its non-self edges, and each new internal edge can
be replaced by an old path. General reachability and condensation edges need
not be unchanged. The ordinary adjacency, invalidation and publication paths
remain responsible for those changes.

The candidate shares the exact old owner/member indices and updates the
existing persistent forward/reverse indices. It classifies only effective
edge differences, after complete replacement validation. A retained-direction
edit does not pay for these extra owner queries. A failed classifier keeps
the original local repair. A successful membership check never authorizes
source currentness or callback effects.

The [[https://github.com/tao3k/lean-poo/blob/511cc4a8d1bfb66778efbb782ac2849acc3b011d/LeanPoo/Functional/OrderedSccRepair.lean][OrderedSccRepair extension at 511cc4a]] proves =component_stable_edit= and
=owner_classified_edit= for all finite graphs. Scheme correspondence checks
mixed internal insertion/external deletion, old snapshots, sharing, and a
functional ring receiving a chord before another edge is removed. A chord
retires the one-successor certificate even though its SCC survives. Keeping
that certificate would make the later split incorrect.

The separate =component-stable-scc-benchmark-test= uses the existing SCC
benchmark entry, 2 GiB heap and 100K/1M cycle/Hub components. Cold capture,
incremental revision and explicit full output are separate observations.
Full equivalence compares groups once and each owner's rows once, avoiding
quadratic copies of a giant member list. The proof alone establishes neither
native work bounds nor Yuanxu 10K Module acceptance. Native qualification
and matched faults below supply the separate implementation evidence.

The exact public proof archive builds all 412 Lean library jobs and its strict
SysML contract passes. Native correspondence currently passes 52 Graph Cases,
including 128 deterministic compound edits. The component-publication control
adds an internal edge, removes an external dependency, changes a value, checks
the outside consumer against cold evaluation, and retains the old result.
Stale and denied submissions retain the installed head. A later edit of the
detached provider recomputes only that provider. The matched cycle-shape fault
fails the original split equality; it is not counted as a compiler refusal.

The preliminary fixed-input comparison used the SDK's default C =-O1= on
both kernels. It is not the project's =-O2= production qualification. Keep that
distinction when reporting its timings or native process accounting. The
native production qualification below is separate; no failed or exploratory
receipt is a production pass.

* Contract and implementation

Cold packed capture already checks every edge and records its direction
relative to the owned roster. Preserve those bits in the existing private
partition shape. A replacement checks only its authored rows against the
same positions. If either direction survives, every SCC is still a singleton:
reuse the existing owner/member maps, and edit the existing persistent
forward/reverse indices. Do not traverse old closure buckets or rewrite
component membership. Self edges are permitted. If the premise fails, keep
the original SCC merge/split repair. An unverified singleton result alone
does not establish a direction certificate.

LeanPoo PR16's [[https://github.com/tao3k/lean-poo/blob/68138245e247451f1c7d8d57572cb8a8ca4331e2/LeanPoo/Functional/OrderedSccRepair.lean][OrderedSccRepair]] proves path monotonicity, singleton component
identity, preservation by exact row replacement, and cold/incremental
membership equivalence. Structural direction does not authenticate source
currentness, replace effect checks, or authorize a publication. Core's
existing GraphSnapshot Quint model remains the separate publication model;
the optimization changes neither its state transition nor ticket rules.

At 100K and 1M vertices, use three ordered shapes: a chain; a middle hub with
half the roster consuming it; and a middle row reading half the roster.
Each edit adds one distinct, non-self dependency to an earlier vertex. The
fixture refuses a duplicate/self edit. Four observations start from the same
old snapshot; sequential mutation coverage remains in the original tests.

Report fixture enumeration, cold prior capture, edited cold capture, sparse
revision, 1,000 warm membership queries, and full output/equivalence separately.
The cold oracle compares complete groups, every owner, dependency row and
membership. Revision requires zero author callbacks and preserves the old
row. For the certified candidate it additionally requires zero forward/
reverse closure buckets/edges, SCC region work, owner/member writes or
rebasing, and an exact changed-edge rank-check count. A matched old kernel
records the whole matrix, then fails the absent work contract.

Use existing Gambit process counters for CPU, wall, GC and allocation. Admit
allocated bytes only when no GC occurred and the native delta is nonnegative;
otherwise report unavailable. Peak RSS is the whole runner process, not an
attributed phase allocation or a VM heap assertion. Do not print internal
POO objects: report numeric work fields only.
