#+title: Simula joint publication: declared shapes and shared definitions

* Scope and implementation
This advances the generalized protocol future work. Reference: poof revision
9affa8fbbb4f12cbd98cb97f8b8b84474fc39429, poof.scrbl 2040–2099
(labelled method fragments, effective methods and negative assumptions), and
ltuo_10_efficient_object_implementation.scrbl 1406–1420 (bounded method cache).
It does not claim a verbatim Racket API or compiler/runtime verification.

~prepare-shape~ compiles an explicitly declared C4 shape only when every selected
candidate is unconditional. It runs no method, guard or invented argument.
Actual calls retain typed argument/current C4 validation. Guarded definitions
stay on the ordinary path; edits invalidate preparation. Negative certificates
transport private witnesses through cache-only successors. The cache stays
bounded at eight shapes. Preparing entries can cause an initially empty
zero-budget publication to refuse earlier; resource admission is not equivalent.

~context-preflight~ separates stable Simula method code from current view data.
The typed view argument is checked on every call. A shared immutable child can
survive capacity/invoice joint revision, while the outer projection, contracts,
negative checking and publication/readmission chain retain current semantics.
No successful result, old view, or mutable cache cell is shared. Every new def
has a contract comment; implementation uses existing FUN/IO and POO composition.

Tests count compilation and body execution separately, check exact child/cache
owner retention across revisions, larger current versus old capacity, revoked
release, malformed invoice, invalid Object arguments, invalidated definitions,
guarded preparation refusal and late budget failure retaining the warm version.
All 28 native test modules passed. Lean proves preparation preserves both cache
invariants/current method semantics, discarded-successor probe equivalence,
nested owner retention, and universal context/captured-view Simula equivalence.
ShapePreparationBudget and ContextPreparationBudget include cold setup, binding,
all calls, added context validation/representation costs and supplied excess GC.
Their selection bounds are conditional cost inequalities, not timing proofs.

* Fair native protocol
Current executable: metadata-paired-simula-context. Ten phase scenarios, six
direct strategy pairs, four ABBA rounds and natural/collected GC regimes:
960 fresh children, 480 pairs. Each child initializes and warms the same ten
controls in a fixed order. Pair positions rotate. Child cap: 20 seconds/1 GiB;
compile/study cap: 90 seconds. No build/test overlapped measurement. Strict
source/binary identity, coverage, order, counter, completion and EOF admission
passed. All pair prefixes match allocation/GC counters; this is not heap identity.

The cold context control constructs a fresh child definition AND model binding
on every operation before complete publication and first call. Steady revisions
reuse the immutable definition. These phases exclude process startup. Configure
constructs a fresh protected child on both sides; generics refreshes the changed
heterogeneous family without body invocation. Probe drops successors; transfer
checks publication invocation and successor readmission; stage includes admission;
revision adds reserve/cancel; repeated adds eight reserve calls/cancel. Allocation
uses one complete revision operation and admits bytes only when both sides have
no GC and nonnegative native counters. No Python timing/measurement engine.
