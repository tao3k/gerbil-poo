#+title: Forwarding, inner, Simula and independent preparation horizons

* Construction and proof scope

The original Appendix B permits arbitrary combinations of sorted labelled
fragments and gives the Racket wrapper/getter/setter construction. Forwarding,
inner and Simula here implement the existing Lean extensions of that direction;
they are not claimed to be verbatim Racket APIs. Unified generalized MOP remains
future work. See ../alignment.md for exact interfaces and remaining gaps.

Native =ForwardContribution.= uses the existing C4 sparse index and typed
arguments/output. Next takes #f to retain payload or =(some payload)= to replace
it, including =(some #f)=. Dispatch is fixed; replacements are validated before
continuation. Guards inspect the initial row once per invocation, including warm
calls. Around changes the inner entry payload; primary changes only its suffix,
so after retains the inner entry payload. Negative inspection executes no body.

=inner= reverses the C4-selected sequence and lets the superclass omit inner.
=SimulaBody.= runs general-first prefixes and specific-first suffixes; failures
stop subsequent parts, with no guaranteed finalizers or external effect rollback.
The publisher separately retains the exact old admitted version on refusal.

New models compose these controls with declarative edits, current invoice
request enrichment, typed preflight, shared generic expansion, contracts and joint
revision. Enriched reserve explicitly adds invoice to its CLOSED dependency
projection. Invoice-only changes rebuild reserve/cancel and retain quote; other
models keep their smaller support. Tests also verify negative cancellation
refusal and old-version identity after late approval refusal.

General laws live in existing Lean Object.MultimethodCombination: forwarding
reference/append/stop, inherited append/stop, Simula ordered pair/prefix failure.
Existing Examples.AlignedServices proves current/revoked enrichment, phase-local
payload and exact effect trace, invoice dependency preservation, superclass
arithmetic and preflight state. TemplateCosts proves check-mode selection,
configuration coverage and the unpaid single-use configuration case.
SelectionCacheCosts.compiled_eq proves hoisted arithmetic preserves choice;
validation_sites counts invariant/argument validation sites, not total machine
instructions or allocation. No source inventory, JSON or coverage flag changed.

* Cold versus sustained use

Single-parent =with-meaning descriptor meaning #f= does not force a shared check
record and clears any inherited record. Meaning remains current; invocation still
checks input, source, output and logic. Ordinary clone construction remains the
cheapest existing fixed-cold source and is reused directly by the factory.

Immutable selector weights and the fallback relation are validated once when
building the callback. Only selection-cost is validated on each callback entry.
Configuration can share that validated policy object rather than constructing
another one. This amortizes first setup; it does not erase initial configuration.
The model explicitly proves a nonzero policy fee cannot be paid by a single-use
fresh mode. Callers knowing they need only that case can use the ordinary source.

=configured-source selector-calls check-uses= compiles TWO independent horizons.
With illustrative weights (not embedded timings), one use selects fresh checks;
64 descriptor uses share checks, while the selector guard price still selects
dynamic. Cold =budgeted-source= is exactly selected-source by identity;
=repeated-source= is exactly shared-checks-source. No per-descriptor cost
interpreter, unused cache, new source owner or wrapper is introduced by a dynamic
choice. Counts/prices are supplied premises rather than a learned performance
oracle. Changed sources/prices require reconfiguration.

The final matrix uses single-parent horizons for cold/stage controls and repeated
template horizons for complete joint/DAG/qualified publication. Repeated-use
weights are not retrospectively fitted to the measured medians. Shared and fresh
checks are both available because their relative cost depends on actual lifetime.

Sharing checks is held equal in complete-publication forced-cache comparisons;
the cold-family comparison changes both check and selector modes. The selector
alone does not explain every full-publication delta. Cold budget construction
itself still adds +17.789us natural / +18.125us collected versus an already
configured shared source. Reuse saves that repetition; first initialization still
costs real work. Collected cold-check CPU savings are mixed even with a lower
residual component. No universal speedup is established.

Controls budgeted/reused-policy are identical outside configure. In complete
publications shared-checks/budgeted also select the SAME source. These A/A controls
expose nonzero process/layout/GC variability: joint +2.941us natural / -4.402us
collected, DAG +1.105us / -2.484us for budgeted -> reused-policy. The identical-source
inner comparison is +2.305us collected with 0/4 faster pairs. Thus even an all-one-
direction small result is not isolated causal evidence for selector overhead.
Native object/cache layouts and GC remain material; some new qualified workflows
still regress. Adverse samples and A/A comparisons are not discarded or relabelled.

All 864 pairs matched prefix allocation-vector and GC counters. Matching counters
do not establish identical heaps. Publication measurements cross collections, so
allocation deltas are unavailable and no allocation reduction is claimed there.
Nested forwarding/preflight examples retain functional generic ownership; their
nested cache successor is not secretly mutated into the published outer method.
Complete timings include cold nested resolution. General prepared effective
methods/nested cache transport remain open and may address that cost separately.

* Retained first iteration and validation

The first 1,728-child run used the single-use check policy for complete workflows.
Its shared-DAG fresh-versus-shared delta was +6.000us natural / +3.223us collected.
That conservative cold policy does not represent sustained template lifetimes.
The native factory and matrix now distinguish the two supplied horizons, and
identity tests prove no extra source pipeline in the sustained mode.
