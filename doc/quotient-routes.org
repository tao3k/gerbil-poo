#+title: Single-pass routes from a captured SCC partition

* Contract before Scheme

=group-code= currently calls =dependencies=, then scans all member rows again
to construct an allowed-node table. Both passes query the same captured SCC
owner index. They are not author evaluation or currentness replay. Capturing
the source and SCC partition remains separate and unchanged.

[[file:quotient-routes.lean][Lean]] proves that one pass returns exactly the ordered provider and
allowed-node lists of the two traversals. The SAME provider deduplicator and
allowed-table construction then have identical arguments and order; the
effectful preparation theorem permits failure and arbitrary semantic state
effects in those actions. [[file:quotient-routes.sysml][SysML]] records the same boundary.

This relies on pure owner lookup in ONE immutable partition. It does not
authorize replacing two arbitrary author callbacks with one, retaining a
lookup across edits, skipping expansion checks, or treating a dependency root
as every external node in its SCC. Graph discovery/certification, source
admission, closure execution and publication are outside the optimized interval.

* Experiment and adoption

Use actual native SCC partitions prepared outside timing. Compare the former
two-pass route preparation with fused preparation, including BOTH original
native table constructors, natural GC and complete ordered/domain equality.
Restore one RNG state to verify native constructor effects, retain all paired
observations and controls. Include an internal-only group and a cross-SCC
group with multiple external nodes sharing one provider root.

The optional phase study uses existing Just heap fences. It is not a real
Interface EVAL, not a new default CI workload, and not alone sufficient to
adopt a production change. Production adoption additionally needs actual
group-code behavior and complete existing feedback/approval/refusal gates.

* Scheme refinement and measured adoption

The production change stays inside =feedback-graph/group-code=. Two nested
standard =with-list-builder= collectors emit ordered providers and nodes in
one traversal. Then the original =delete-duplicates/hash= runs, followed by
the original =make-hash-table-eq= and ordered node insertions. Evaluation and
its undeclared-node/missing-provider checks are unchanged. No row/owner getter
is an author callback here: =partition= and =partition-owned= install native
captured table/index lookup closures. The pure interval does not mutate those
indexes or span a source edit. No retained route cache is added.

The first candidate used cons/reverse for nodes. It passed the semantic/RNG
checks but added a second temporary node spine. It was replaced by a standard
list-builder before adoption. The first experiment also exposed a missing
runtime import for a white-box private reference; that failed run is retained,
and the ordinary Gerbil dependency import was corrected. No loader workaround.

The final study includes complete original and production =group-code= bodies
on the SAME native partition. Each observation constructs 512 fresh computation
objects, using a 32-member SCC. The external shape has 32 provider nodes in
another SCC; internal edges remain present. Partition preparation and final
read/domain oracles are outside timing. A builder that raises on execution
asserts zero business evaluation during construction.

| Routes, internal only | 9.5690 | 4.1800 | 15.9709 | 4.3435 |
| Routes, cross SCC | 133.1570 | 116.9260 | 135.4045 | 134.6114 |

Retain same-side controls too: complete cross-SCC A/A CPU
132.574/129.566 ms and B/B 97.248/98.720 ms. Paired cross-SCC GC counts are
1/1/0/1 versus 1/1/1/1. The internal-only B/B route wall control is slower
than its paired median (30.880 ms); it is not discarded or attributed to
host contention without evidence. Cross-GC signed allocation is unqualified.
These are repeated fresh group construction costs, NOT cold process startup,
million-owner scheduling, Interface admission or first business .get.

The final optional study passes 3 cases with all module/case/harness/final
markers and natural exit (9.90 s wall, 5.49 user, 0.52 system; peak invocation
RSS 393,920,512 bytes). The earlier two phase studies remain separate artifacts.
Four Lean theorems pass Lean 4.35.0 using only propext, without sorry. They
verify the stated algorithm model, not the Gerbil compiler/runtime itself.

The production regression uses provider observations whose first-occurrence
and rightmost-occurrence orders DIFFER; expected deps are =(z x)=. It evaluates
an external nonrepresentative node =y= successfully, and rejects an internal
undeclared node. Both ordinary and owned native SCC partitions are covered.
The matched native fault changes =add-node node= to =add-node owner=. It exits
1 with a real ERROR CHECK on the successful =y= evaluation (undeclared external
SCC read), plus harness failures; neither compiler failure nor timeout is
counted as fault detection. The production source is restored afterward.

After restoration, the complete feedback suite passes 56 cases, including the
stronger ordering case, natural exit and all required markers (30.69 s wall,
13.36 user, 1.51 system; peak invocation RSS 604,897,280 bytes). This includes
existing source mutation, stale authority, refusal, revision and old-snapshot
controls. The new optimization does not alter publication state transitions;
QNT has not been rerun and no new QNT result is claimed.

Construction/cache/order-repair also passes all 44 cases (5.75 s wall,
3.18 user, 0.61 system; peak invocation RSS 430,800,896 bytes), with required
markers, natural exit and no error/overflow. Source checks and snapshot
isolation are not weakened to obtain these results.

* Existing publication integration

The unchanged =owned-quotient-benchmark-test= passes its frozen 1000/10000
group publication, no-op, revision and historical-demand fixture through
compiled native modules and Just, within an outer 180-second watchdog and
the unchanged 2GiB POO heap fence. Invocation: 11.10 s wall, 5.86 user,
0.82 system; peak invocation RSS 933,068,800 bytes; natural exit, all markers.
This is a POO publication fixture with two real scalar groups and inert
remaining groups, not 10,000 Interfaces or Core's 4GiB acceptance.

At 10000 groups, cold full publication takes 2592.006 ms CPU / 3354.019 ms
wall, including 809.833 ms GC CPU and 12 collections. There is no old/new
full-publication comparison here, so no total cold speedup is asserted.
Two same-predecessor edits take 1.674/1.362 ms CPU (1.725/1.405 wall), each
with exactly one source row, two inverse buckets, two value writes and 15
guard-node writes; no code-witness changes or full order materialization.
No-op controls check zero source rows, inverse buckets, value/guard writes.
The final 1000 historical demand calls take 0.290 ms aggregate CPU / 1.518 ms
wall. This is warm demand, not first business evaluation.

Cold publication remains a separate unresolved optimization target. The
route improvement does not close Core 10K Module EVAL or downstream build
gates, and no downstream revision is promoted on this evidence.
