#+title: Cold Graph preparation: empty topology and sparse inverse rows

* Contract before Scheme

The cold path currently stores N empty reverse buckets, then fills incoming
edges in admitted topological owner order. An inverse point read already has
an empty-list meaning when no reader exists; owner membership belongs to the
support/rank index. [[file:graph-cold-index.lean][Lean]] proves equal ordered rows after every edge
insertion and every complete edge sequence, starting from dense empty buckets
or an empty sparse map. The rule is only for inverse reads with default [].
An explicit negative example rejects extending it to arbitrary defaults.

For owned snapshots, the roster is unique and admitted before row acquisition.
After ALL captured rows are empty, DFS has no child visits and emits that exact
roster. Lean proves the empty-DFS order under uniqueness. Keep a private copy
of the order spine, row capture, witness checks and native table constructor
effects. Do not infer emptiness from missing source or skip author getters.
[[file:graph-cold-index.sysml][SysML]] records the same boundaries.

Uncontrolled source handling retains its original full validation/traversal
and dense initialization, including native key checks. Forward row semantics,
generic index absence/false/default behavior, cycle refusal and all callback
checks stay unchanged. No new projection, cache, loader, public API or runner.

* Experimental plan

Separate topology-only and inverse-only construction at 100K/1M nodes. Charge
fresh construction in each window; prepare common admitted rows separately.
Compare empty, chain and hub inverse shapes in native tables, retaining ordered
bucket equality, physical bucket counts and default RNG-state equality.
Keep ABBA/BAAB plus A/A/B/B, natural GC and every slower sample.

Only after measuring a benefit: implement the owned specialization in the
existing schedule functions, audit every private inverse read, exercise first
edge insertion/deletion/retirement and old snapshots, and retain the standard
work oracles. Force a false emptiness claim as a matched fault. Compare complete
old/new cold setup and controlled revisions on identical native test artifacts.

Universal sparse initialization is rejected: the 1M chain is slower, with
different collection placement. No sample or unfavorable control is discarded.
The candidate therefore uses sparse inverse storage only for owned zero/one
provider graphs. A constant-space private classifier consumes already captured
rows: #f=no edges, symbol=one provider, #t=multiple providers/invalid row. It
short-circuits once the multiple-provider case is known. This is a topology
certificate, not a size threshold, retained cache or new public flag. Native
normalization guarantees admitted rows contain distinct symbol dependencies.

The all-empty certificate also avoids DFS and the redundant second inverse
pass. ALL original row captures still occur, and constructors stay in their
original positions. Multi-provider and uncontrolled paths retain their normal
DFS/dense inverse construction; every private inverse consumer uses [] while
forward/generic-index missing/default behavior remains unchanged.

* Functional and refusal gates

The eight Lean theorems, including the classifier-to-all-empty binding, pass
Lean 4.35.0 with only propext/Quot.sound and no sorry axiom. The private Scheme
sentinels are disjoint because admitted provider identities are symbols.

After restoration, construction passes 44 cases (6.82 s wall, 3.25 user,
0.64 system) and SCC/feedback passes 55 cases (45.41 s wall, 12.08 user,
1.27 system). Each has Module/Harness/final OK, natural exit and no error or
overflow marker. Cases retain author-read invocation, no business evaluation,
owner-domain membership, first edge insertion, old empty snapshots, hub versus
chain storage and unknown-source dense behavior.

Two isolated native-compiled faults exit 1 with real harness failures:

- Bypass DFS for every owned graph: an owned cycle is accepted, failing the
  explicit cycle-refusal assertion (and an existing source/value check).
- Omit the inverse empty default on first edge insertion: a valid revision
  fails with UnboundKeyError for its supported provider instead of succeeding.

The first mutation record is retained too; direct cycle/unsupported assertions
were added so rejection is tied to that exact obligation, rather than an
unrelated later failure. Original inverse reads, generic index defaults and
source guards remain separately tested. No timeout or compiler error is used
as evidence that either fault was caught.
