#+title: Cold Graph preparation: empty topology and sparse inverse rows

* Contract before Scheme

The cold path currently stores N empty reverse buckets, then fills incoming
edges in admitted topological owner order. An inverse point read already has
an empty-list meaning when no reader exists; owner membership belongs to the
support/rank index. [[file:graph-cold-index.lean][Lean]] proves equal ordered rows after every edge
insertion and every complete edge sequence, starting from dense empty buckets
or an empty sparse map. The rule is only for inverse reads with default [].
An explicit negative example rejects extending it to arbitrary defaults.

For owned snapshots, the roster is unique and admitted before row acquisition.
After ALL captured rows are empty, DFS has no child visits and emits that exact
roster. Lean proves the empty-DFS order under uniqueness. Keep a private copy
of the order spine, row capture, witness checks and native table constructor
effects. Do not infer emptiness from missing source or skip author getters.
[[file:graph-cold-index.sysml][SysML]] records the same boundaries.

Uncontrolled source handling retains its original full validation/traversal
and dense initialization, including native key checks. Forward row semantics,
generic index absence/false/default behavior, cycle refusal and all callback
checks stay unchanged. No new projection, cache, loader, public API or runner.

* Experimental plan

Separate topology-only and inverse-only construction at 100K/1M nodes. Charge
fresh construction in each window; prepare common admitted rows separately.
Compare empty, chain and hub inverse shapes in native tables, retaining ordered
bucket equality, physical bucket counts and default RNG-state equality.
Keep ABBA/BAAB plus A/A/B/B, natural GC and every slower sample.

Only after measuring a benefit: implement the owned specialization in the
existing schedule functions, audit every private inverse read, exercise first
edge insertion/deletion/retirement and old snapshots, and retain the standard
work oracles. Force a false emptiness claim as a matched fault. Compare complete
old/new cold setup and controlled revisions on identical native test artifacts.
