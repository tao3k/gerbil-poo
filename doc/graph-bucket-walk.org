#+title: Stream incident checks from the existing inverse index

* Scope

Unknown-source =reschedule= still authenticates all owner identities. Controlled
=schedule-revision= binds a ticket to the precise predecessor and forks the
existing structural indices. This change is inside =repair-order= only: checking
incoming incident edges previously materialized =reverse-bucket-members= before
visiting them. The existing =%for-each-reverse-bucket= already visits that exact
sequence without building the retained-owner list.

* Contract before Scheme

[[file:graph-bucket-walk.lean][Lean]] proves traversal over additions followed by a masked base equals
traversal over their materialized concatenation. The step can fail and carries
arbitrary prefix state: first refusal and every preceding counter/trace update
are preserved. Gerbil's standard =rbtree-for-each= walks left/node/right;
=rbtree-foldr cons= visits right/node/left while prepending, yielding the same
ascending sequence. Both forms retain base order. [[file:graph-bucket-walk.sysml][SysML]] records the boundary.

Mask preparation and membership must remain pure on this private immutable
bucket. No author callback or Gerbil expansion is moved across a check. Public
bucket/order enumeration, source capture, SCC and publication are unchanged.
This removes an intermediate list, not the necessary O(degree) incident check.

* Acceptance

Extend the existing deletion/re-addition test with ordered streamed/materialized
comparison and refusal-prefix comparison for each historical bucket, including
single and multiple masks. Preserve the construction group's independent order,
cycle, invalidation and snapshot controls. Use the existing Just/Gerbil entries.
Runtime performance and exact-head CI are separate from the Lean equivalence.

The optional =inverse-walk-test= in =benchmarks/cold-preparation-test.ss= compares
the former list-then-visit operation with the existing streaming visitor on the
same admitted 100K/1M bucket. It retains ABBA/BAAB and A/A/B/B observations,
natural GC and exact visit counts; it is absent from default builds and CI.
This kernel is separate from complete rank repair and does not eliminate the
explicit enumeration cost when a caller actually requests a bucket's members.

* Native results

Lean 4.35.0 accepts all three theorems, with no sorry axiom (only propext for
the filtered-list equalities). The existing construction group passes all 42
cases across both modules. Deliberately reversing the plain bucket iterator
causes a real =ERROR CHECK= at the new ordered-prefix assertion: =(a b c)= versus
=(c b a)=, exit 1. Restoring and recompiling the implementation restores all
42 cases and natural exit (4.96 s wall), with Module/Harness/final OK. The
optional study passes all nine cases and exits naturally (5.71 s wall).

* Search over an edited bucket in a partial interval

=editedSearch_exact= extends the stream proof to the search frontier. It
returns the same ordered accepted owners followed by the original pending
tail. Its edge count includes all live readers, including those outside the
interval. The Scheme visitor allocates a fresh cell for each accepted owner
and relinks that private prefix. Complete intervals and plain rows use the
existing search path.

The native fixture removes one reader before adding an edge that requires
rank repair. The edited row then has one reader inside the interval and one
outside it. The test checks the exact resulting order, three visited buckets,
two live edges and three changed ranks. The existing reverse-bucket study
also checks the exact output, shared tail and live-edge count on each sample.

Native CPU medians in ms, four samples per arm, original versus streamed:

|------+--------+-------+--------+-------|
| 100K | natural | 1.37 / 1.07 | 1.33 / 1.06 | 2.54 / 1.50 |
| 100K | collected | 1.38 / 1.14 | 1.30 / 1.06 | 1.89 / 1.42 |

The 1M natural empty pair had almost equal wall medians at 18.68 and
18.58 ms. The 1M natural dense reference had one collection in one sample.

A separate run of the same study reported 1,062,010,880 bytes maximum RSS
for the complete harness, including both arms and their shared inputs.
Removing the rank predicate in an isolated native build made the new
fixture visit four buckets instead of three and fail with exit 42.
Restoring the predicate passed all 28 cases in the Graph order module.

* Retiring an inserted reader

An insertion into an edited inverse bucket records whether the absent
edge had a mask over the borrowed row. Removing the insertion keeps that
mask only for a borrowed reader. An insertion absent from the borrowed
row leaves neither an ordinal entry nor a mask. The transition does
not search the borrowed spine. =discard_absent_base_mask= proves that
dropping the redundant mask preserves the ordered borrowed output.

The first insertion also preserves the distinction between the admitted
spine and later readers. Removing the last outstanding insertion returns
the original spine if no mask remains. The native regression checks
pointer identity and the intermediate snapshot's order.
=first_insertion_then_removal_restores_row= checks the ordered output.

The regression adds and removes 10,000 distinct readers of one edited
bucket. It checks the remaining edit count, re-removal of a borrowed
reader, and the order of both predecessor and successor snapshots.

The existing mixed-owner, ring, hub and reverse-bucket studies passed at
100K and 1M vertices with the 2 GiB Scheme heap fence. At 1M the mixed
edit repaired four owners and visited three quotient reader edges.
Its two incremental samples took 0.087 and 0.173 ms CPU, allocated
242,368 bytes each and triggered no GC. The cold controls took 3.449
and 3.602 s CPU. The ring and hub deletion windows took 0.064 and
0.065 ms CPU, each removing one reverse edge without rewriting its
bucket. Maximum RSS for the complete invocation, including fixture
preparation, cold controls and explicit output, was 2,736,816,128 bytes.

The matched fault build, which always retains the deletion mask, also
served as the reference for a separate four-process comparison in
reference/candidate/candidate/reference order. Each process used the
same 10,000 distinct insert/remove pairs on both prepared reader spines.
Four samples per size checked exact ordered output and the predecessor
row. For the 1M spine, eight samples per arm produced these ranges:

| Window | Retain masks CPU, ms | Drop redundant masks CPU, ms | Retain masks wall, ms | Drop redundant masks wall, ms |
|--------+----------------------+------------------------------+-----------------------+--------------------------------|
| Edits  | 16.96–29.22          | 5.39–11.97                   | 16.96–76.51           | 5.39–23.14                     |
| Demand | 103.25–161.84        | 8.25–14.69                   | 117.75–427.88         | 8.25–145.93                    |

All measured windows had zero collections. The 1M edit window allocated
47,465,616 bytes with retained masks and 23,200,400 bytes when dropping
them. Explicit demand reported 529,312 and 480 bytes respectively.
The demand wall-clock ranges overlap. These windows isolate one prepared
inverse bucket, and peak RSS was not collected for this comparison.

10,000-pair workload at both sizes on its existing prepared spines.
It checks exact ordered output and requires a single retained mask.
The study is available through =just benchmark-scc= and the same suite
filter used for the other Graph studies.
