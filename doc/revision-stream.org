#+title: Revision currentness: stream fixed fields, retain every boundary

* Contract before Scheme

The closure and finite-lens guards compare a captured revision list with
=map object-revision sources=. Every successful check constructs a temporary
list which is immediately discarded. The source and version spines are private
proper lists of valid objects and captured revisions. The fixed
=object-revision= implementation reads =object-%state= and its revision field;
it performs no Slot getter, author callback or source-observer operation.

[[https://github.com/tao3k/lean-poo/blob/bbba642946c7ef98c98eee52387013e9da2fd171/LeanPoo/Proof/Gerbil/RevisionStream.lean][Four Lean theorems]] prove direct structural comparison equals streamed
comparison, different lengths refuse, changes to unrelated owners are irrelevant,
and arbitrary accept/refuse continuations remain identical. Lean 4.35.0 accepts
all four with only propext/Quot.sound and no sorry. The initial unrelated-owner
proof needed an explicit map rewrite; its failed output is retained locally.

Two additional work-count theorems pass the same Lean check: a fully current
list requires one field read per owner; with k matching entries followed by a
mismatch, exactly k+1 fields are read, independent of the suffix. These are
counts of modeled field reads, not claims about machine time or synchronization.

These proofs depend on a pure total reader. They do not license this change
for arbitrary getters, a throwing reader, malformed private storage, or concurrent
raw metadata mutation. Native field behavior is a separate refinement obligation.
[[file:revision-stream.sysml][SysML]] records the same limits.

The shared internal helper lives beside =object-revision=. The two callers
keep their original error messages, active-source protection and independent
checks at each existing boundary. No earlier verdict crosses compilation,
expansion or an author callback. Capturing a revision snapshot still uses
=map=; only comparison with that snapshot changes. No cache or evaluator is added.

* Fixed same-process native comparison

The optional =benchmarks/revision-stream-test.ss= runs through existing Just.
Each prepared source is a distinct real POO object. Preparation is outside
BOTH arms. Sizes 8/64/1024 represent source metadata in guards, not Module
discovery or million-node Graph traversal. Each timed observation executes
1024 checks. Keep ABBA/BAAB, A/A and B/B, current/head-stale/tail-stale scenarios,
natural GC and all raw observations. These are separate guard workloads.

This establishes a pure comparison/allocation improvement. Complete publication,
Module EVAL and downstream construction require their own gates; a measured
kernel gain does not close them. Production adoption also requires an actual
matched functional fault and restored native integration, recorded below.

Current-case A/A versus B/B CPU medians (milliseconds) are respectively
0.2305/0.2180 at 8 sources, 1.6150/1.0890 at 64, and 36.9005/17.5760 at
1024. The 1024 A/A pair includes one collection; all B/B observations have
zero collections. Retain the small-case variation: no universal fixed speedup
factor is claimed from submillisecond windows.

* Matched failure oracle

An isolated compiled fault makes =fragment-sources-current?= always true.
The original stale-publication test still passes because a later residual
check can reject the candidate. That observation is a gap in the old oracle,
not evidence that the missing entry guard is acceptable or was caught.

Strengthen that same existing stale case, without a new suite: call the entry
boundary with an explicit action, require the original stale-source error,
and require the action to remain unentered. This distinguishes early source
refusal from an unrelated later failure. Raw outputs from both oracle versions
are retained locally.

The strengthened oracle does fail against the same successfully compiled
fault: =ERROR CHECK= reports =failure result: entered= instead of an error
object, then =ERROR HARNESS= and exit 1. The supplied action demonstrably ran.
The fault is then restored and the production module recompiled before any
integration gate. No compiler error or timeout is counted as fault detection.

The first generalized-group invocation could not start because its compiled
test interface was absent in the qualification prefix (exit 70). Preserve that
output as preparation failure. The existing =just build-group generalized=
then supplies the interface; do not call the missing-file failure a functional
refusal or rerun already passing unrelated groups to hide it.

Restored serial local gates pass: objects 171 cases, feedback 60, generalized
33, construction 44, plus the frozen 1K/10K owned-publication case. All have
Module/Case/Harness/final OK, natural exit and no error/overflow marker.
Publication invocation is 21.82 s wall / 6.94 user / 0.94 system, peak RSS
941326336 bytes, under the unchanged 180-second/2GiB POO limits. Its 10K cold
window is 3133.054 ms CPU / 8984.123 ms wall, including 916.076 ms GC CPU
and 12 collections. This is a single candidate run, so it does not establish
an end-to-end speedup. The original and streamed kernel comparison above
cannot be used in place of the complete publication comparison.

* Matched complete publication

Run the frozen =owned-quotient-benchmark-test= through Just in separate
processes, reference/candidate/candidate/reference. Both arms share the same
fresh native object unit, =cc319ed= Graph unit, fixture and other test artifacts.
Reference guards come from the exact =cc319ed= archive. Only
=generalized-declaration.ss= and =lens-laws.ss= differ; both arms are built
with =-O2=, and only the candidate generated code calls the streamed helper.
The 180-second watchdog, 2 GiB heap, natural GC and all original work oracles
stay unchanged. The outer shell initially tried to unset zsh's reserved
=status= variable after the first completed arm. Its successful process
and receipt are retained, and the other three arms continue in the original
order using a regular variable.
