#+title: Issued reads use their declaring record fields

* Problem and contract

A read signature binds the final slot-read constructor's physical fields and
ordered parent identities. The cold traversal used reflective slot-ref for
parents, while the issuer checked a fixed field. Editing only the class's
symbolic dependencies mapping redirected a four-record closure to two records;
a modified original parent then escaped replay. A new issuer could also bind
wrong field meanings if created after an inspection-map edit.

The signature, cold traversal, live value check and redelivery now use the
slot-observation module's existing generated field operations. Issuers stamp
the declared birth field through that module's generated setter. These are
private bindings; public key/value/dependency inspectors retain their copies.
HashTable reflective-route offset checks, per-record signature/state checks,
callback-return verification, root order and duplicate delivery remain.

This corrects the signed-row oracle used by the existing DFS; it introduces
no new Graph algorithm, loader, cache, public API or compatibility path.

* Verification

- Three ordinary-import regression cases cover cold closure completeness,
  rejection of a changed original parent, and issuer creation after key/value/
  checker/parent/birth display-map edits.
- The public 7f6e68a artifact fails the first two semantic assertions: 2 vs 4
  records, and missing parent refusal. Restoring only reflective traversal in
  the fixed artifact reproduces both failures. Restoring only factory field
  recapture fails the new-issuer assertion while the other two cases pass.
- The restored artifact passes all 242 cases across issuance/field layout,
  inheritance, representations, declaration indexes, order repair and Graph
  feedback; the expanded issuance suite also passes as a compiled interface.
- The three regressions join the existing issued-read suite (35 cases) in
  the existing objects group. No build script, test partition, CI job,
  aggregate rerun or alternate runner is changed.

Core's original 10K 180-second/4-GiB gate and real downstream acceptance remain
separate open gates. This repair does not establish a full Module EVAL speedup.

* Local same-record study

The frozen public selector and repaired selector share the current issuer and
the same 8,858 real Interface reads: four ABBA samples per arm, 12 passes per
sample. This isolates traversal/selection; it is not an original-vs-repaired
issuer binary comparison. CPU medians in milliseconds:

| Work | Frozen selector | Repaired selector |
|------+-----------------+-------------------|
| Cold selection | 80.2095 | 79.2245 |
| Warm complete replay | 72.9315 | 75.3860 |
| Cold complete replay | 201.6770 | 191.4745 |
| Warm protected checkpoint | 149.7350 | 154.7675 |
| Cold protected checkpoint | 234.1490 | 219.4165 |

All GC samples and wall-clock gaps are retained. Mixed warm/cold results do
not establish a stable performance win. The independent correctness repair
is qualified by the graph/issuer controls above, not by a claimed EVAL gain.
